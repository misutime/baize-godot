## 1. GPU 加速验证（Win）——结论：正常；0 帧是静态页正常行为

### 1.1 硬件归属实证
- `nvidia-smi`：CEF GPU 进程（CefViewWing.exe）与 Godot 同在 **GPU 0 = RTX 4080 SUPER**
- `EnumDisplayDevices`：主显示 DISPLAY1 = RTX（PRIMARY，4K@160Hz）；GameViewer 虚拟显示
  （UU 远程组件）未连接
- GPU 进程模块：`nvwgf2umx.dll`（NVIDIA D3D11 驱动）+ d3d11/dxgi，无 `vk_swiftshader.dll`
- **误判纠正链**：初判"WARP 路径"→ 被 nvidia-smi 推翻（`WarpPal.dll` 是 Chromium 预加载
  fallback，加载≠使用；`nvoglv64.dll` 是 OpenGL 驱动，D3D11 路径本就不加载）

### 1.2 产帧机制（留档，维护必需）
- **GPU 模式 OnPaint = CefVideoConsumerOSR → FrameSinkVideoCapturer 捕获合成帧 → 读回 CPU**；
  软件模式（`--disable-gpu`）无 video_consumer，走 HostDisplayClient 直接 Draw
- **`windowless_frame_rate=60` = OnPaint 最大频率**（CEF 设 compositor VSync 参数 16.67ms +
  capturer 最小捕获周期）；GPU 模式 60fps 即此上限；软件模式不受限（实测 117fps）
- **静态页 0 帧是正常行为**：OSR 只在有 damage（动画/滚动/交互/resize）时产帧
- **测试方法教训**：中途 `stage_webview` 把动画测试页还原成 stub，无意中换掉变量——
  A5/A7（动画页）60fps vs A9+（静态页）0 帧。**"系统 idle/远程会话触发"误判被推翻**
  （F3 用动画页在相同 idle 状态复现 60fps）

## 2. CEF 集成契约修复——internal BeginFrame + 每帧泵送

### 2.1 shifu 源码级分析（CEF 151 源码）
- 宿主两处契约违例：① `OnScheduleMessagePumpWork` 丢弃 `delay_ms`（只置 bool）；
  ② `SendExternalBeginFrame` 错绑消息泵请求（官方 cefclient 用独立定时器）
- **`begin_frame_pending_` 闩锁**（`render_widget_host_view_osr.cc:1175`）：一次 accepted BF
  未收到 `OnFrameComplete(BeginFrameAck)` 前，后续 `SendExternalBeginFrame` 全部静默 return——
  work=50/s 的尝试可等于 1 accepted + 49 drop
- **`hold_resize_`**：`WasResized` 首次设置，只有收到目标尺寸 OnPaint 才释放——"尺寸永不变化"
  是首个新尺寸 paint 未到的背压结果，**不是 hidden 证据**

### 2.2 修复（三变体实验定案）
| 变体 | 结果 | 结论 |
|---|---|---|
| V0 现状（external BF + 节流泵） | 动画页 60fps | 正常态可用，自维持循环脆弱 |
| V1（每帧泵 + 独立 60Hz BF） | 主线程阻塞 | 高频 BF 在合成器停顿态卡死 |
| V2（internal BF + 节流泵） | 0 帧 | **节流泵饿死内部帧源** |

**最终修复**：`external_begin_frame_enabled = 0`（CEF 内部帧源按 `windowless_frame_rate=60`
驱动）+ **每帧泵送**（`CefDoMessageLoopWork` 每 Godot 帧；internal BF 的帧处理依赖消息泵
持续运转，静态页无工作时开销≈0）+ 删除 `SendExternalBeginFrame`。
附带清理死代码 `kPumpWarmupFrames` / `pump_frame_count`（修复后不再参与判断）。
**mac 需复验**（共享代码，机制平台无关）。

## 3. C0.4 JS 双向桥排障——根因：页面调用签名错误

- **现象**：Win 多轮 0 条 query 日志（注入看似失败）
- **排障**：宿主 `consoleMessage` 临时日志捕获 renderer console——`typeof cefViewQuery =
  function`（注入正常），但页面调用报 `Uncaught Error: Invalid arguments; expecting a
  single object`
- **根因**：CEF 官方 `CefMessageRouter` 注入的函数要求**单对象参数**
  `{ request, persistent, onSuccess, onFailure }`；页面旧代码 `cefViewQuery(req, callback)`
  多参数在 renderer 侧参数校验即失败，query 从未发出 IPC
- **修复**：`modules/webview/ui/bridge.html` 改官方单对象签名；验证 5 次 reload 无悬空
  callback（query_id 干净递增）
- **非 CefViewCore 机制缺陷**（此前审查：配对表/生命周期/挂钩均正确）

## 4. 输入事件转发（B 项）——全链路 + 双 reviewer 修复

### 4.1 分层实现
- `webview_core`：`send_mouse_move/click/wheel`、`send_key_event`、`set_focus`（纯 C++ 标量
  参数映射 `CefMouseEvent`/`CefKeyEvent`）；`focus_on_editable` 按 BrowserEntry 隔离
  （focusedEditableNodeChanged 回调按 id 更新）
- `web_panel`：GUI 输入捕获（**`gui_input` 信号连接**——Godot 4 `_gui_input` 非虚函数，
  C++ 控件标准模式）；Godot Key → Windows VK 映射；焦点管理（FOCUS_CLICK + grab_focus）
- `webview_manager`：纯透传中转

### 4.2 关键映射逻辑（留档）
- **VK 映射用 `physical_keycode`**（Shift+1 的物理键是 KEY_1；逻辑 keycode 对 Shift 标点
  EXCLAM 无对应 VK）
- **ASCII 直通仅空格/数字/A-Z**；标点走 `VK_OEM_*`（0xBA-C0/0xDB-DE）——修复前
  `Key::APOSTROPHE`(0x27) 被当 `VK_RIGHT`(0x27)，标点会发错键码
- **`accept_event()`**：每个转发成功分支消费事件，防 Godot 双响应（Tab 移焦点/Ctrl 快捷键
  穿透/滚轮穿透）；未映射键不消费保持向外传播
- **echo 重复键**：补 CHAR + `EVENTFLAG_IS_REPEAT`（Windows 每次 WM_KEYDOWN+WM_CHAR 合并进
  echo，只发一次 CHAR 会丢重复字符）
- **滚轮 factor**：`120 * factor`（Windows factor = delta/WHEEL_DELTA，高精度保留）
- **补充平面字符**：`U+10000+` 拆 UTF-16 代理对发两次 CHAR（emoji 不截断）
- **unmodified_character 独立传递**：Alt/Ctrl 组合取物理键基础 ASCII（CEF 快捷键判定）
- Godot 枚举坑：`Key::DELETE` 实际叫 `KEY_DELETE`（Windows 保留字）；`Key`/`MouseButton`
  已去 `KEY_`/`MOUSE_BUTTON_` 前缀；`callable_mp` 在 `core/object/callable_mp.h`

### 4.3 验证
系统级模拟输入（mouse_event/keybd_event + MapVirtualKey 扫描码）：`move/down/up/click` 全链路
到达页面 JS；`'a'`→keyCode 65、`','`→keyCode 188（OEM 修复生效）

## 5. WebUI 架构决策（协议层设计依据）

- **主通道 CefViewClient 桥对象**（`invokeMethod` 调用 + `addEventListener` 事件 + C++
  `TriggerEvent` 下行 + `__cefview_report_js_result__` 回报）——唯一同时具备调用+事件
  的通道；`cefViewQuery` 仅因已实现保留备用，**不作开发目标**
- **invokeMethod 是 fire-and-forget**：返回通道自建 = req_id + `method_result` 应答事件
  （TriggerEvent 下行，SDK 封装 Promise）；req_id 约定**字符串**（JS 数字 → C++ double）
- **参数载体**：CefListValue 字符串化（对象参数由前端 JSON.stringify）；`invokeMethodNotify`
  在 webview_core 做基础类型→字符串，协议层 JSON 解析
- 详见《Godot编辑器UI重构方案-TS路线-WebUI架构-桥协议与前端SDK.md》

## 6. 协议层落地（C 项）——方法注册表 + 事件下行

### 6.1 代码路径（留档）
- `webview_core.cpp` `invokeMethodNotify` → `on_invoke_method` 回调（`std::vector<std::string>`）
- `webview_manager.cpp` `_on_invoke_method`（静态）→ `WebBridge::handle_invoke`
- `web_bridge.cpp` 方法注册表：`scene.get_node_count` / `scene.create_node`(undo) /
  `editor.undo` / `editor.redo`；未注册方法显式 `method_not_found` 报错
- `scene.create_node`：`memnew(Node3D)` + `EditorUndoRedoManager::create_action("WebUI Create
  Node")` + `add_do_method(root,"add_child",node,true)` + `add_undo_method(root,"remove_child",
  node)` + `commit_action()`；返回 `instance_id`
- 事件下行：`WebBridge::_respond` → `emit_event("method_result", JSON)` →
  `webview_core::emit_event` → `CefProcessMessage(kCefViewClientBrowserTriggerEventMessage)`
  （arg0=事件名，arg1+=字符串参数）→ `CefViewBrowserClient::TriggerEvent` →
  renderer `OnTriggerEventNotifyMessage` → `ExecuteEventListener` → JS 监听器
- `scene.get_node_count`：递归统计场景根后代（含根自身）

### 6.2 验证（cef-smoke-test 项目）
```
get_node_count → 1 → create_node("WebNode") → 2 → undo → 1 → redo → 2
```
- **method_result 事件下行全链路首次实测通过**（TriggerEvent → JS addEventListener）
- 错误路径：`no_scene`（无主场景项目）、`nothing_to_undo`/`nothing_to_redo`、
  `method_not_found`——JSON 结构 `{ok:false, error:{code,message}}` 正确
- **测试项目需有主场景**：cef-b0-test 无场景 → no_scene 正确；验证用 cef-smoke-test
