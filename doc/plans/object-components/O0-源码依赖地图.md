## 5. NodePath 使用（1308 处）——引用机制迁移策略

NodePath 是最大迁移面，但不是每个使用点都要替代：

| 使用类别 | 迁移方式 |
|---|---|
| 场景内静态引用（`get_node("A/B/C")`） | → `StableObjectId` + Relation（§4.7/§14.7） |
| 资源内的 NodePath 属性（`.tscn` 序列化） | → `.bscene` 内 `StableObjectId` |
| 运行时动态查找（信号参数等） | → `RuntimeGameObjectHandle`（EntityId + Generation） |
| 动画/骨骼绑定路径 | → 动画后端内部实现细节（不暴露 C# API） |
| 编辑器选择路径 | → `ObjectSelection`（O7） |

> 硬约束（方案 §1.1/§8.1）：C# 产品 API 不出现 NodePath/get_node；后端内部的 NodePath 是私有实现细节。

## 6. SceneTree（1057 处）/ MainLoop —— 主循环拆分层

`SceneTree : public MainLoop`（scene/main/scene_tree.h:89）当前维护的全部职责（§2.2）：
process group / physics group / 排序与线程组 / Node 增删改事件 / group map / current scene / root Window / timers/tweens / multiplayer / physics interpolation / delete queue / accessibility queue。

**目标分层**（§14.5，非 `GameWorld : MainLoop`）：

```text
GameWorld                 // 纯运行时世界，可测试、可服务器复用（O1 建成）
BaizeMainLoop : MainLoop  // Godot 进程宿主（O5）
GameWorldNodeHost : Node  // 迁移期 SceneTree 宿主（O5，桥接）
EditorPreviewHost         // 编辑器预览宿主（O7）
```

- `GameWorld` 职责（O1 就独立建立，防 §12.2 风险「GameWorld 只是 SceneTree 包装」）：对象 registry、组件生命周期、Parent/Relation、Tick 调度、服务端口、运行时状态。
- `SceneTree` 只作为迁移期宿主，O8/O9 关闭默认路径。

## 7. PackedScene/SceneState（344+215 处）——序列化主语义替换

现状：`PackedScene::pack(Node*)` / `instantiate()` + `SceneState` 记录 Node 类型/名称/parent/owner/属性/NodePath/信号（§2.6，`.tscn` 承担 Scene+Prefab 双语义的根源）。

目标（§6）：新增 `BSceneResource/.bscene`、`BPrefabResource/.bprefab`，内部记录 ObjectRecord/ComponentRecord/ParentRecord/RelationRecord/ResourceReference/PrefabInstance/Override/SceneSettings。`.tscn` 只做一次性导入（迁移完成移除 loader）。

**Series 化替换顺序**：O1 先做「确定性序列化」内核（GameWorldSnapshot round-trip）→ O4 定义 `.bscene/.bprefab` 最小格式与实例化计划 → O6 场景可从 `.bscene` 加载。

## 8. C# binding 使用清单（O3 前补充）

- 现状：`modules/mono/glue/` 生成的 managed glue 绑定所有 ClassDB 类型（含全部 Node 族）。
- 目标（§8.3）：新增 `GameObject/GameWorld/GameComponent` ClassDB 注册 → 生成 C# managed 绑定 → Component Schema source generator → 默认模板只暴露 GameObject/Components；Node 类型移 Advanced/Backend 命名空间或禁用默认生成。
- 本清单在 O3 阶段产出详细 per-type 绑定清单。

## 9. 可直接复用的 Server API（不重写）

- `RenderingServer`（RID 接口）、`PhysicsServer2D/3D`（Jolt）、`NavigationServer`、`AudioServer`、GPU 粒子后端、Mesh/Material/Texture 资源系统、输入底层、平台/窗口后端、C# Roslyn/Reload 基础设施（§3.1/§3.2）。
- 迁移只重构这些系统之上的「场景实体组织层」。
