## 3. 最近三次关键改动（你接手时要理解的设计脉络）

这三个改动是本会话对 O2 的收敛，**都已在 master**：

### 3.1 显式阶段顺序替换 MotionPlan（`912f179032`）

- **为什么**：原"每对象 MotionPlan"抽象被判定为"极高心智负担、非社区自造轮子"。社区（Unity DOTS `FixedStepSimulationSystemGroup`、Flecs `PreUpdate/OnUpdate/PostUpdate`、Bevy xpbd `SweptCcd`）都用**显式阶段顺序**解决同一问题（先全局移动再碰撞的顺序无关）。
- **改法**：`RunFrame` = `MoveAll`（玩家→敌人→子弹到本帧终点）→ `CollideAll`（子弹读双方 `Position→PreviousPosition` 扫掠命中）→ `world.Tick`（开火/生成 OnTick）。删 `MotionPlan`/`PlanMotion`/`PlanPhase`/`MoveAction`。
- **顺序无关的根据**：所有移动先于所有碰撞完成；碰撞读的是各方**已更新好的**本帧线段，与创建/执行顺序无关。

### 3.2 多来源暂停 + MatchController 纯状态化（`621b49889f`）

- **为什么**：单一 `Paused` bool 无法承载多来源语义（菜单 vs 终局）。对齐社区"暂停计数/分层 + 状态即门禁"。
- **改法**：新增 `PauseManager`（`HashSet<string>` 多来源计数，`Pause/Unpause` 去重幂等）。`MatchController` 删 `_world`/`Bind`，`RequestGameOver` 只切 `Phase`（纯状态，不碰世界）。`ShooterGame.RunFrame` 是**唯一聚合点**：`ApplyPause` 读各来源（PauseManager + 终局 Phase）→ 写入 `world.Paused`；帧首 + Move 阶段后各读一次（敌人接触触发终局**当帧冻结**）。
- **约定**：资源一律 `world.AddResource(new Xxx())` + 构造传参，**不用 `Bind`/后门**（保持"纯状态资源 + 组合根读状态得出门禁"的单向因果）。

### 3.3 生命周期回调内改结构不中断暂停刷新（`f882af27a7`，reviewer P1）

- **为什么**：`GameWorld.Paused` setter 与 `RefreshEffective` 直接枚举 `_hierarchy.Roots`/`store.All`/`GetChildren`，而 `OnEnable/OnDisable` 回调解法上可在枚举期间改结构（销毁对象/增删组件）→ 抛 `Collection modified`。
- **改法**：三个遍历点都**物化快照**（对齐已有 `TickSnapshot` 语义）。新增回归测试 `Test_暂停回调内改结构不中断刷新`。O1 内核从 147 → **150 项通过**。
- **注意**：这种"遍历前物化快照"是 O1 内核的**既定模式**（`TickSnapshot`/`AllObjects` 同款），后续写遍历结构的地方都应遵循。

## 4. 下一步 O3 该开发什么（§14.10 修订版）

**O3 = GameObject C# bindings + Component Schema**。当前代码里 **Component Schema 已提前实现大半**（`ComponentSchema.cs` 已有 `[GameComponent]`/`[GameProperty]`/单/多实例/`Requires`），所以 O3 的**剩余工件**是：

### 4.1 GameObject C# bindings（核心新增）

这是 O1 内核到 `GameObject` 实际"能用"/"能进引擎"的桥接层。具体要做的：

1. **C# 属性 → 引擎元数据的映射**：把 `[GameProperty]` 标记的字段，暴露给引擎（Inspector/序列化/反射读取）。当前 `GameWorldSerializer` 已做确定性序列化；O3 要补"**Schema 驱动**"的反射/元数据层，让组件字段能被引擎遍历而不硬编码。
2. **稳定性键**：序列化类型键已统一为稳定全限定名（R7），但 O3 要确保 `.bscene/.bprefab` 格式（O4 才有，见 §4.2）能用这些键做可读、可 diff、Git 友好的存储。
3. **Schema 校验整合**：`Requires` 依赖校验已实现（R14）；O3 补"未知组件/未知属性"的容错与明确报错。
**验收方向**（从修订路线 §14.10）：一个 `GameObject` 能在 C# 里被 Schema 驱动地创建、查询、序列化、往返一致，且不依赖任何 Node/ECS API。

## 5. 关键概念与坑（接手前必读）

### 5.1 阶段顺序（O2 的核心，不要回退到 MotionPlan）
- `RunFrame` = `MoveAll` → `CollideAll` → `world.Tick`。顺序无关靠"所有移动先于碰撞"，**不要**重新引入每对象运动计划。
- `Move` 阶段顺序固定 玩家→敌人→子弹：玩家先动，敌人 `Move` 读玩家当前 `Position`（即本帧终点）作为寻向目标。

### 5.2 多来源暂停（不要回退到 bool 直接推）
- 资源是纯状态；只有组合根（`RunFrame.ApplyPause`）读各来源后写 `world.Paused`。
- 新暂停来源 = 在自己状态里加一个 `Pause(source)`/`Unpause(source)`，组合根聚合自动纳入。

### 5.3 只读防"幽灵扫掠"（no-phantom 不变式）
- 一个**不移动**的对象（禁用 / 无玩家可寻）必须 `prev=pos` 退化为静止点，否则子弹扫掠会沿它的旧运动段误判命中。`EnemyControllerAction.Move` 的两个提前返回分支（`!CanTick` 和 `FindPlayer()==null`）都必须退化 `prev=pos`——**新增任何"不移动"分支都要记得退化**。

### 5.4 O1 内核遍历：先物化快照
- 任何在"回调内可能改结构"处遍历集合的地方（Roots/GetChildren/store.All/_tickOrder），先物化副本，避免 `Collection modified`。已有 `TickSnapshot`/`AllObjects`/`RefreshEffective` 三处同款。

### 5.5 `CanTick` ≡ O1 `IsTickable`
- O2 的 `ShooterWorldHelper.CanTick(comp)` 等效 O1 `IsTickable`（对象存活 + 对象/父链 Enabled + 组件 Enabled + 世界非 Paused）。改一边要同步另一边。

### 5.6 文档即权威
- 改 `GameWorld` 行为必须先改 `O1-GameObject语义契约.md`（R1–R21）。改 O2 玩法先把 `HUMAN_FIRST_AUTHORING.md` 更新。
- **术语已对齐**：`EntityId→ObjectId`、`AddService/GetService→AddResource/GetResource`、`SpawnTickIndex→CreatedAtTickIndex`、`Service→Resource`、`Behavior→Action`、`Step→RunFrame`、`ShooterWorld→ShooterWorldHelper`。写新代码/文档**必须用新术语**，不要引入旧的。
