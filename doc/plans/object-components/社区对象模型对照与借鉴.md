## 1. 调研对象与结论一句话

对照了 **Unity/Unity DOTS、Flecs、Bevy、EnTT、Stride、WaveEngine、Defold** 七个社区成熟（或曾经主流）的对象/组件模型。

> **结论：O1 内核与社区模型高度同构**（身份/生命周期/关系/预置体/事务/场景格式均对得上），没有结构性缺失。差异集中在「存储布局」（我们 O1 用轻量 class 组件，DOD 只做可选后端）与「通信方式」（我们默认 C# 直调 + Relation，Defold 式消息队列仅可选）——这两点都是方案 §14.2/§14.6 的有意决策，非遗漏。

## 2. 逐项对照

### 2.1 已对齐（我们的设计有社区验证）

| 维度 | 社区实践 | 来源 | 我们的实现 |
|---|---|---|---|
| 对象 = 组件集合 | Unity `GameObject+Component`；Stride `Entity+EntityComponent` | [Flecs Designing](https://www.flecs.dev/flecs/md_docs_2DesignWithFlecs.html) / [Stride ECS 用法](https://doc.stride3d.net/latest/en/manual/engine/entity-component-system/usage.html) | `GameObject` + `ComponentStore`（单/多实例宽口） |
| 实体身份防复用 | EnTT entity versioning（id + generation） | [EnTT entity](https://github.com/skypjack/entt/blob/master/docs/md/entity.md) | `EntityId(Index, Generation)`，Generation 递增防 stale handle |
| 生命周期顺序 | Unity `Awake→OnEnable→Start→Update` 家族；Defold 脚本回调 | Unity 手册惯例 / [Defold addressing](https://defold.com/llms/manuals/addressing.md) | `OnCreate→OnEnable→OnStart→OnTick/OnFixedTick→OnDisable→OnDestroy` |
| 非父子关系 | Flecs Relationships（`(relationship, target)` 对，可挂数据） | [Flecs Relationships](https://www.flecs.dev/flecs/md_docs_2Relationships.html) | `RelationGraph` + `GameRelation` 数据类 |
| 组件组合配方 | Bevy `Bundle`；Unity 组合多个脚本 | [Bevy scene](https://docs.rs/bevy/latest/bevy/scene/) | bundle 概念（P2 ECS 已有 `IEntityBundle`；O2 GameObject-first 复刻） |
| 预置体实例修改 | Unity prefab per-instance modifications | [Unity 序列化](https://unity.com/blog/engine-platform/serialization-in-unity) | 契约 §8 `(ObjectId, ComponentType, PropertyPath, Value)` override 记录 |
| 场景格式前瞻 | Bevy BSN（scene/template/patches） | [Bevy scene](https://docs.rs/bevy/latest/bevy/scene/) | `.bscene/.bprefab`（O4 规划） |
| 运行时加载链路 | Unity `Instantiate`、Bevy `spawn(scene)` | [Bevy scene](https://docs.rs/bevy/latest/bevy/scene/) / [Unity 序列化](https://unity.com/blog/engine-platform/serialization-in-unity) | `GameWorldSerializer.Restore`（snapshot → 世界） |

### 2.2 值得借鉴（约定采纳，见 §3）

| # | 借鉴点 | 来源 | 落地阶段 | 吸收方式 |
|---|---|---|---|---|
| B1 | **核心组件自动附带（Required Components）**：Transform 等随对象创建自动挂上，scene 不再手写壳 bundle | [Bevy PR #15579](https://github.com/bevyengine/bevy/pull/15579) | **O2 前** | `CreateGameObject` 自动加基础组件，或依赖链（`Requires`）表达同等保证 |
| B2 | **C# 数据契约序列化**：`[DataContract]/[DataMember]` 驱动编辑器与序列化 | [WaveEngine 自定义组件](https://geeks.ms/waveengineteam/2015/09/18/custom-components-and-renderproperty-attributes-on-wave-engine-2-0-part-1/) | **O3** | 我们的 `[GameComponent]/[GameProperty]` 与之一致，生成器/编辑器走同一条路 |
| B3 | **Prefab override 记录格式**：per-instance modifications 的权威实现 | [Unity 序列化](https://unity.com/blog/engine-platform/serialization-in-unity) | **O4** | `.bprefab` override 具体格式照 Unity 记录方式细化（契约 §8 已定性） |
| B4 | **状态查询/校验**：`is_alive()`、稳定句柄 + 命名调试 | [Flecs Designing](https://www.flecs.dev/flecs/md_docs_2DesignWithFlecs.html) | 已实现 | `IsAlive/GetObject`；O6 编辑器寻址参考作用域思想（最终用 Relation） |
| B5 | **轻量 System 接入**：组件即触发对含该组件集合的处理 | [Stride ECS 用法](https://doc.stride3d.net/latest/en/manual/engine/entity-component-system/usage.html) | **O6+** | 批处理后端照 `DefaultEntityComponentProcessor` 模式，不引入 Archetype 全盘约束 |
| B6 | **帧内消息队列解耦**（可选）：对象间异步消息 + 回调 | [Defold message passing](https://defold.com/llms/manuals/message-passing.md) | O2 按需 | 命中/死亡事件若解耦需要，借鉴 Defold 帧内排队 + `on_message`；默认保持 C# 直调简单 |

### 2.3 明确不借鉴（有意决策，非遗漏）

| 不借鉴内容 | 原因 | 依据来源 |
|---|---|---|
| DOTS 的 **Archetype/Chunk 默认存储** | 普通对象走轻量 class 组件；SoA/Archetype 只作可选性能后端（profiling 证明热点才引） | [Unity DOTS](https://unity.com/blog/engine-platform/on-dots-entity-component-system) / 方案 §14.2 |
| **EnTT 稀疏集/池作唯一存储** | O1 正确性优先；批量场景 O6 再 SoA | [EnTT entity](https://github.com/skypjack/entt/blob/master/docs/md/entity.md) |
| Unity 早期 **重 OOP MonoBehaviour 每实例虚表** | 轻量 class 组件，无重型包装 | Unity 手册架构惯例 |
| Flecs **深 DOD/查询 DSL 为主开发面** | 保留 O1 可读性；批量才下沉 | [Flecs Designing](https://www.flecs.dev/flecs/md_docs_2DesignWithFlecs.html) / 方案 §14.2 |
| Godot **Node 树作对象模型** | 本方案立场：Node 降为内部后端 | 方案全篇 |

## 3. 采纳决策（已定稿，供各阶段执行）

- **B1（O2 前强制）**：GameObject-first Shooter 的对象创建不再样板化——`CreateGameObject` 支持「创建即带基础组件」，或经 `Requires` 依赖链保证核心组件存在。O2 验收含「对象创建零样板」检查点。
- **B2（O3）**：C# 组件 Schema（`[GameComponent]/[GameProperty]`）的序列化语义与 WaveEngine DataContract 模式对齐；编辑器 Inspector 与序列化共用同一 Schema。
- **B3（O4）**：`.bprefab` override 记录格式以 Unity per-instance modifications 为权威参照细化（不另立新格式）。
- **B5（O6+ 可选）**：批量处理用 Stride processor 模式的轻量接入（组件集合 → 系统），不引入 Archetype 作为默认。
- **B6（O2 按需）**：仅当事件解耦确实需要时才加帧内消息队列；默认 C# 直调。
