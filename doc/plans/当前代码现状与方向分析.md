## 3. 当前架构（现状，以 HEAD 代码为准）

### 3.1 总体拓扑

```
┌─ Godot 编辑器进程（fork 增量）───────────────────────────────┐
│  modules/att_editor_ops  能力唯一事实源（Registry + Ops + UiTree）│
│        ▲ 委托                    ▲ 透传                        │
│  modules/att_webview ──────┐  modules/att_nodejs_sidecar      │
│  （CEF WebDock 通道）       │  （WS server + 进程监督）          │
└──────────┬─────────────────┼──────────┬───────────────────────┘
           │ CefViewClient IPC│          │ WebSocket（127.0.0.1:port0）
           ▼                 │          ▼
┌─ CEF 渲染进程 ──────────────┘  ┌─ Node 进程（web/runtime）──────┐
│ web/ui（React 属性面板壳）      │ GodotClient → JSON-RPC 2.0   │
│ web/packages/sdk（协议适配）    │ services/echo（S1 仅此）       │
└───────────────────────────────  └──────────────────────────────┘
```

两通道能力面同为 `Registry`（AGENTS.md 分层规则 + 实施原则文档）；双通道协议机制同构但四维不同
（传输/信封/角色/错误语义），现状刻意不收敛（《双通道协议收敛-评估方案》结论）。

### 3.2 `modules/att_editor_ops` — 编辑器领域能力面

- **Registry**（`registry.{h,cpp}`）：能力注册表唯一事实源。**17 个方法**：
  `ui.*` 4（get_tree/activate/set_text/focus）、`editor.*` 9（select_node/set_prop/get_state/undo/
  redo + get_ui_font_size/scale/font/font_bold）、`scene.*` 4（get_node_count/create_node/
  get_node_position/set_node_position）。参数用 JSON Schema（properties + required），
  `validate_args` 统一校验（registry.cpp:232）。惰性注册（`ensure_registered`，幂等）。返回统一
  `{ ok, result } / { ok:false, error:{code,message} }`。
- **Ops**（`ops.{h,cpp}`）：操作实现，组合引擎既有 API（EditorUndoRedoManager / EditorSelection /
  Control），含类型转换/路径守卫（禁止绝对路径/`..`）/只读拒绝。**引擎仍是唯一执行者**，ops 只做
  组合/契约/防护。字体解析路径存运行时存储（`Ops::set_resolved_fonts`，非持久化——防机器绝对路径
  写入 editor_settings）。
- **UiTree**（`ui_tree.{h,cpp}`）：遍历 EditorNode 的 Control 树导出语义快照（role/name/state/
  children/items；TreeItem 用 `<树控件 id>/item/<索引>…` 路径编码）。
- 零依赖，`TOOLS_ENABLED` 门控；`register_types.cpp` 为空（静态惰性，无单例）。

### 3.3 `modules/att_nodejs_sidecar` — Node sidecar 通道（S1 完成）

- **SidecarServer**（`sidecar_server.{h,cpp}`，710 行）：Godot 侧 WS server（复用引擎 websocket/wslay，
  仅回环 `127.0.0.1:0`，端口经 env 下发）。
  - 协议：**严格 JSON-RPC 2.0 子集**（自做解析，不用引擎 JSONRPC 类——其 handler 返回值无条件进
    result、无 error.data）：一帧一 document、request id 一律 string、batch 显式拒绝（-32600）、
    server 拒 response 输入；错误码 -32601/-32602/-32000，内部字符串码入 `error.data.code`。
  - 认证：双令牌（spawn 模式随机 32B hex 生成，仅内存 + env 下发；dev 模式要求父环境显式
    `BAIZE_SIDECAR_TOKEN`）；`sidecar.hello` 首帧校验，deadline 3s；错误令牌断开 + 告警。
  - 分派（`_dispatch`）：`sidecar.hello/health/echo/subscribe` 自身方法 + **Registry 全量透传**
    （`find` + `validate_args` + handler，零新增注册路径）。subscribe 目前仅登记空表回执（S2 生效）。
  - 资源预算：MAX_CLIENTS 4、输出队列 16 MiB high-water、单帧 64 消息、入站 buffer 4 MiB
    （语义树快照 ~780KB）。
  - 生命周期：EDITOR 级 MessageQueue 第一帧启动（register_types.cpp）；崩溃检测（每帧 `is_running`）
    → 退避重启 0.5/1/2/4/8s 封顶 ×3，稳定 5min 重置，第 4 次不再自动重启；spawn 失败同路径重试；
    退出编排：shutdown 通知（直发 + poll 泵送）→ 等 2s → kill 进程树。
  - 入口解析：`BAIZE_SIDECAR_ENTRY` 覆盖 > 开发期自动发现 `<exe_dir>/../web/runtime/dist/index.js`
    （exe 在 bin/，仓库根 = bin/..，零配置）；入口缺失一次性报错引导 `pnpm build`，不进入退避重试。
- **ProcessSupervisor**（`process_supervisor.{h,cpp}`）：补齐 `OS::create_process` 缺失的
  per-spawn env/cwd/stdio/进程树能力（不改 OS 抽象）：env 增量注入（token 不落 argv/日志，
  显式 argv 泄露防护）、stdout/stderr 重定向 `user://logs/sidecar.log`（>5MB 轮转保留 1 份）、
  Windows Job Object（KILL_ON_JOB_CLOSE + CREATE_SUSPENDED 绑定成功前不放行）、Unix setsid +
  killpg；不可用不静默降级（Job 绑定失败即终止 spawn）。

### 3.4 `modules/att_webview` — CEF WebDock（非 OSR 窗口模式，最终态）

- **WebViewCore**（`webview_core.{h,cpp}`）：纯 C++ 核心层封装 vendored CefViewCore
  （`thirdparty/cefviewcore/`）。公开 API 面零 Godot 类型（std::string/std::function，防 CEF 头与
  Godot enum 重名 C2365）；`external_message_pump=1`，主线程泵送；非 OSR `SetAsChild` 原生子窗口
  （像素零回传、输入/IME 原生直达）；shutdown 有界泵等待（3s，超时显式报错不 CefShutdown）；
  每实例独立 cache 槽位（文件锁，多编辑器实例）；日志经回调转发到 Godot stdout（GUI 输出面板可见）。
- **WebViewManager**：浏览器实例管理（create/resize/visible/navigate/destroy）+ 帧泵；焦点双轨修复
  `poll_focus_return`（Godot 鼠标按下沿归还键盘焦点，弃用 GetAsyncKeyState；b45ad072fd 进一步修复
  模态对话框抢焦点）。
- **WebPanel**：Godot 控件壳（子窗口矩形同步/可见性/加载事件）；仅支持宿主主窗口根视口
  （嵌入视口/CanvasLayer 层级显式告警）。
- **EditorWebDock**：dock 注册（LEFT_UL，加载 `file:///…/webview/ui/index.html`）+ 事件源接线。
- **WebBridge**（`web_bridge.{h,cpp}`）：**10 个桥方法全部委托 Registry**（`_dispatch_semantic`，
  纯协议适配层：req_id 字符串包装 + 返回形状适配，如 create_node 三元组 → 裸 instance_id）。
  事件下行：`method_result` 应答事件 + `TriggerEvent` 事件源（selection_changed /
  node_position_changed / undo_stack_changed / scene_changed，帧轮询 diff 推送 + 信号连接
  `EditorSelection::selection_changed`、`EditorSettings::settings_changed`）。**当前单浏览器目标**
  （`set_event_browser_id`，S2 重构多目标 fan-out）。
- `cef_application_mac.{h,cpp}`：macOS CrAppProtocol 注入。

### 3.5 `web/` — pnpm workspace（顶层仅宿主，packages 收被消费库）

- `runtime/`（@baize/sidecar）：S1 主路径 = GodotClient 连 Godot WS（hello 握手 + 退避重连 +

## 5. 方向（以决策文档与代码注释为准）

1. **TS 路线**：WebDock 属性面板是第一步（React 壳），编辑器 UI 逐步 TS 化；前端经 CEF 承载
   （非 OSR 窗口，像素零回传）。
2. **能力统一原则**（《实施原则-编辑器领域能力统一editor_ops.md》）：新能力三步走
   （Ops 实现 → Registry 注册 → 通道自动获得）；**通道禁止新增 if/else 能力实现**；读写一视同仁
   （查询同样是能力）。能力清单可审计（`Registry::methods()`）。
3. **sidecar 恒启用地基**（9ecfc37741 决策）：Agent/LSP/资产管线宿主的承载进程；不提供关闭路径，
   无 Node 明确报错引导安装；开发期零配置入口，发布期 SEA 打包进 exe（`BAIZE_SIDECAR_ENTRY`）。
4. **S2 计划**（文档预告）：sdk 接入 sidecar JSON-RPC（@baize/rpc 已声明消费者）→ 届时按双通道
   收敛**方案 A**（CEF 通道统一 JSON-RPC 2.0 信封，三端类型单一来源；触发条件：S2 排期 / 类型漂移
   CI / 第三通道）；事件声明归 editor_ops、事件源多目标 fan-out、订阅表生效。
5. **未来通道**：Node MCP server（att_editor_ops README 预告；协议形态在通道三设计时定，倒逼
   收敛决策）。
6. **中文优先**：全链路 UTF-8（CEF ↔ Godot ↔ 协议 JSON ↔ 文件）；String 智能解码使 C++ 中文字面量
   直接可用。
7. **分发**：macOS 非 AppStore 正式版发布计划（`doc/plans/发布计划-macOS正式版分发-非AppStore.md`）；
   构建脚本已支持 bundle 内自包含（运行时/UI 入 .app，a2c29a676f）。

## 6. 已知边界与风险

- **双通道协议异构**（CEF 自定义信封 vs sidecar JSON-RPC）是现状刻意（《收敛评估》方案 C）；重复的
  配对机制 + 两份类型声明靠人肉对齐，类型漂移 CI 未落地——S2 启动时按方案 A 收敛。
- **String 智能解码**与上游合入的冲突面：FORK-CUSTOM 修改了 `String(const char*)` 契约（行为变化：
  Latin-1 字节串中合法的 UTF-8 序列现在按 UTF-8 解码）；纯 ASCII 串多一次 O(n) 合法性扫描
  （注释称内存带宽级，无感知）；上游若改动该构造需人工合入。
- **事件源单浏览器目标**：`set_event_browser_id`，S2 需多目标 fan-out。
- **WebPanel 仅主窗口根视口**：嵌入视口/CanvasLayer 层级不支持（显式告警）。
- **能力面无测试覆盖**：codegraph 显示 `validate_args`/`register_method` 等无 covering tests；
  TS 侧有测试（transport/registry/jsonrpc/godot-client/ws/echo），C++ 侧靠实机验证。
- **运行依赖 Node**（开发期）：入口缺失/无 Node 时 WS 监听保持但不 spawn；发布期靠 SEA 消除。
- **体积**：CEF SDK 下载与 `bin/webview/` 运行时（数百 MB 级）、思源字体 ~33MB（Regular+Bold
  OTF 进 bin/webview/ui）；日志 5MB×1 轮转。
- **非 OSR 取舍**：CEF 原生子窗口带来输入/IME/渲染零成本，但 WebPanel 层级受限、窗口置顶等平台
  交互需宿主桥接（焦点双轨修复 b45ad072fd 即此类问题）。
