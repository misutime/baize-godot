## 2. 第二日目标与范围

**目标**：打通"页面可交互"全链路——JS 双向桥（C0.4）→ 输入事件转发 → undo 集成雏形。

**两条独立管道**（勿混淆，都属 MVP2 地基）：
- **双向桥**（C0.4）：JS↔C++ 命令/数据通路（CefMessageRouter `cefViewQuery`），承载 create_node/undo/count/属性同步
- **输入事件转发**：鼠标/键盘/焦点 → CEF（`SendMouseClickEvent`/`SendMouseMoveEvent`/`SendKeyEvent`/`SendFocusEvent` + IME），让页面可点击可输入

**验收场景**（参考旧测试页功能，页面不迁移）：
1. 页面按钮"创建节点"→ 桥命令 → 编辑器场景创建 Node3D，且**可撤销**
2. 页面"撤销上一步"→ 回退编辑器操作
3. 页面"查询场景节点数"→ 返回真实数量
4. 页面 input 可聚焦、可输入英文（IME 中文输入留 C0.5）

## 3. 工作项拆解（按依赖顺序）

### A. C0.4 JS 双向桥 Win 排障与验证【✅ 完成 2026-08-03】【原先阻塞 C，现已解除】

**根因（页面签名错误，非注入/路由）**：`window.cefViewQuery` 注入完全正常（renderer `OnContextCreated` 执行，
`typeof = function`），但页面 stub 用 `cefViewQuery(req, callback)` 多参数调用——CEF 官方
`CefMessageRouter` 注入的函数要求**单对象参数** `{request, persistent, onSuccess, onFailure}`，多参数在
renderer 侧参数校验即失败（`Uncaught Error: Invalid arguments; expecting a single object`），query 从未
发出 IPC → 宿主永远 0 条日志。**非 CefViewCore 机制缺陷**（此前审查确认的配对表/生命周期/挂钩均正确）。

**修复**：`modules/webview/ui/bridge.html` 改用官方单对象签名（已正式写入，含注释）。

**验证（Win 实机）**：
- [x] 请求/响应双向通过：宿主 `[WebView] query: id=0 query_id=1 body=ping` → JS `onSuccess echo: ping`
- [x] 刷新无悬空 callback：5 次 reload，query_id 干净递增（1→5），无 Uncaught/异常
- [x] 干净版冒烟：CEF initialized → page loaded 200 → query 正常

**排障工具**（已移除）：宿主 `consoleMessage` 回调临时日志（证明其诊断价值——页面 JS 错误/注入状态
可暴露到编辑器控制台，后续可考虑正式保留）。

### D. Win IME（C0.5）【✅ 完成 2026-08-03（基础版）；候选窗定位/样式后置】

**实现（基础版：组合文本转发 + 上屏）**：
- `webview_core`：`ime_set_composition` / `ime_commit_text` / `ime_cancel_composition`（映射
  `CefBrowserHost::Ime*`；replacement 用 `CefRange::InvalidRange()`）
- `web_panel`：`NOTIFICATION_OS_IME_UPDATE` 处理（与 TextEdit 同模式）；FOCUS_ENTER/EXIT 激活/释放
  IME 管道（`window_set_ime_active` = ImmAssociateContext + CreateCaret）；组合中抑制 CHAR；
  IME 提交合成事件（keycode=NONE）专用分支只发 CHAR

**排障记录（3 轮根因，全部源码级定位）**：
1. **输入法切换无效**：缺 `window_set_ime_active(true)`（IME 管道未激活）→ FOCUS_ENTER 激活（LineEdit 同模式）
2. **上屏拼音/空白**：Godot `ime_get_text()` 只读 `GCS_COMPSTR`（微软拼音只给拼音），上屏汉字以
   key CHAR 事件到达；组合结束改 `ImeCancelComposition`（不提交拼音），上屏汉字经专用 CHAR 分支
3. **英文恒大写 + 中文控制符**（shifu）：**CEF 151 Windows OSR 的 CHAR 路径用 `windows_key_code`
   作字符载荷**（`FromCharacter`，忽略 character 字段）——CHAR 的 windows_key_code 必须传 unicode
   （'d'→100），传物理 VK（68='D'）恒大写；中文上屏传 vk=19=U+0013 变控制符
4. **中文插到文本开头**（shifu）：`CefRange(0,0)` 表示"无替换范围"错误——Chromium 151 视零宽
   [0,0) 合法 → `SelectRange(0,0)` 把 caret 强移偏移 0 → 组合建在开头；改用 `CefRange::InvalidRange()`
   （cefclient 同款），组合锚定点击后的 caret

**验证（用户实机手动）**：英文大小写跟随 CapsLock 正常、中文上屏正常、光标位置正常。

**Review 修复（2026-08-03，reviewer 审查后落地）**：
- P1：IME 激活绑定"页面可编辑节点聚焦"（`focusedEditableNodeChanged` 回调到面板 `set_focus_editable`）——
  非编辑节点聚焦时激活 IME 会截获按键（Windows 丢弃 WM_KEYDOWN 给输入法）
- P2：IME 更新按 OS 窗口焦点隔离（`NOTIFICATION_WM_WINDOW_FOCUS_IN/OUT` 跟踪 `window_has_focus`）——
  `ime_get_text` 读的是 OS 焦点窗口，多窗口时防组合串注入错误 browser
- P2：组合光标 UTF-32 → UTF-16 换算（`new_text.substr(0, sel.x).utf16().length()`）——组合串含
  补充平面字符时偏移不再错位
- P2：IME 提交分支（keycode==NONE）清除组合状态——Windows WM_IME_ENDCOMPOSITION 不发
  IME_UPDATE，不在此清会导致状态滞留、后续可打印键被组合抑制逻辑丢弃

**遗留（完整版/UI）**：候选窗定位到输入框（`OnImeCompositionRangeChanged` + `ime_set_position`）；
组合文本黄色高亮是 Chromium UA 内部样式——**React 壳（MVP3）UI 设计时用 `::composition` CSS 解决**；
`GCS_RESULTSTR` 暴露后改走 `ImeCommitText(result)`（长期语义完整）；surrogate 代理对 windows_key_code
已对应（webview_core send_key_event）。

## 4. 风险与注意事项

- **桥排障可能触及 thirdparty CefViewCore**（注入缺陷）：优先绕过（宿主侧补注入），避免改 vendored 代码

- **设备缩放**：`getScreenInfo` 现 device_scale_factor=1.0，坐标映射先按 1:1，后续接 DisplayServer 缩放
- **每帧泵送**（今日修复）已 Win 实测 60fps，mac 复验待排期（共享代码）
- 旧测试页仅参考验收场景，不迁移（其 `sendIpcMessage` API 为 godot-cef 时代，与 CefViewCore 的 `cefViewQuery` 不兼容）
