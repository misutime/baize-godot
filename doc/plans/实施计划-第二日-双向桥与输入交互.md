## 2. 第二日目标与范围

**目标**：打通"页面可交互"全链路——JS 双向桥（C0.4）→ 输入事件转发 → undo 集成雏形。

**两条独立管道**（勿混淆，都属 MVP2 地基）：
- **双向桥**（C0.4）：JS↔C++ 命令/数据通路（CefMessageRouter `cefViewQuery`），承载 create_node/undo/count/属性同步
- **输入事件转发**：鼠标/键盘/焦点 → CEF（`SendMouseClickEvent`/`SendMouseMoveEvent`/`SendKeyEvent`/`SendFocusEvent` + IME），让页面可点击可输入

**验收场景**（参考旧测试页功能，页面不迁移）：
1. 页面按钮"创建节点"→ 桥命令 → 编辑器场景创建 Node3D，且**可撤销**
2. 页面"撤销上一步"→ 回退编辑器操作
3. 页面"查询场景节点数"→ 返回真实数量
4. 页面 input 可聚焦、可输入英文（IME 中文输入留 C0.5）

## 3. 工作项拆解（按依赖顺序）

### A. C0.4 JS 双向桥 Win 排障与验证【✅ 完成 2026-08-03】【原先阻塞 C，现已解除】

**根因（页面签名错误，非注入/路由）**：`window.cefViewQuery` 注入完全正常（renderer `OnContextCreated` 执行，
`typeof = function`），但页面 stub 用 `cefViewQuery(req, callback)` 多参数调用——CEF 官方
`CefMessageRouter` 注入的函数要求**单对象参数** `{request, persistent, onSuccess, onFailure}`，多参数在
renderer 侧参数校验即失败（`Uncaught Error: Invalid arguments; expecting a single object`），query 从未
发出 IPC → 宿主永远 0 条日志。**非 CefViewCore 机制缺陷**（此前审查确认的配对表/生命周期/挂钩均正确）。

**修复**：`modules/webview/ui/bridge.html` 改用官方单对象签名（已正式写入，含注释）。

**验证（Win 实机）**：
- [x] 请求/响应双向通过：宿主 `[WebView] query: id=0 query_id=1 body=ping` → JS `onSuccess echo: ping`
- [x] 刷新无悬空 callback：5 次 reload，query_id 干净递增（1→5），无 Uncaught/异常
- [x] 干净版冒烟：CEF initialized → page loaded 200 → query 正常

**排障工具**（已移除）：宿主 `consoleMessage` 回调临时日志（证明其诊断价值——页面 JS 错误/注入状态
可暴露到编辑器控制台，后续可考虑正式保留）。

### B. 输入事件转发（鼠标/键盘/焦点）【✅ 完成 2026-08-03】

**实现**（全链路）：
- `webview_core.h/.cpp`：新增 `send_mouse_move/click/wheel`、`send_key_event`、`set_focus`（纯 C++ 标量参数，
  映射 CEF `CefMouseEvent`/`CefKeyEvent`）；`focusedEditableNodeChanged` 回调跟踪
  `focus_on_editable` 状态（键盘事件 `focus_on_editable_field` 权威来源）
- `webview_manager.h/.cpp`：中转方法（面板 → 核心层，纯透传）
- `web_panel.h/.cpp`：GUI 输入捕获（`gui_input` 信号连接，C++ 控件标准模式）；鼠标（move/click/wheel）、
  键盘（RAWKEYDOWN+CHAR/KEYUP，echo 只补 RAWKEYDOWN）、焦点（FOCUS_CLICK + grab_focus + FOCUS_ENTER/EXIT）、
  鼠标离开（leave）；Godot Key → Windows VK 映射（ASCII 直通 + 常用特殊键表）

**验证（Win 实机，系统级模拟输入）**：
- [x] 鼠标全链路：系统鼠标 → Godot `_gui_input` → CEF → 页面 JS，`move/down/up/click` 全部到达
      （页面经 cefViewQuery 上报，宿主日志 `evt:click:286:834` 等）
- [x] 键盘全链路：点击聚焦后系统按键 'a' → 页面 `keydown e.key='a'`（VK 0x41 映射正确）
- [x] 坐标映射正确（面板本地坐标 → OSR 视口像素）；页面加载/退出正常

**遗留**：IME 中文输入（C0.5，依赖本项已就绪）；未映射键（Godot Key → VK 表外）静默跳过。

**Review 修复（2026-08-03，双 reviewer 审查后全部落地）**：
- P1：各转发分支 `accept_event()`（防 Godot 继续处理同事件——Tab 移焦点/Ctrl 快捷键/滚轮穿透）
- P1：ASCII 标点改走 `VK_OEM_*` 映射（修复前 `Key::APOSTROPHE`(0x27) 被当 `VK_RIGHT`；实测 `','` → keyCode 188 正确）
- P2：VK 映射改用 `physical_keycode`（Shift+1 物理键=KEY_1，逻辑 keycode 对 Shift 标点无 VK）
- P2：`focus_on_editable` 移入 BrowserEntry（按浏览器隔离，随条目销毁，不跨浏览器串状态）
- P2：键盘 echo 重发 CHAR + `EVENTFLAG_IS_REPEAT`（按住可打印键不再只插首字符）
- P2：补充平面字符（U+10000+）拆 UTF-16 代理对发两次 CHAR（emoji 不再截断成 U+F600）
- P2：`unmodified_character` 独立传递（API 扩展；Alt/Ctrl 组合取物理键基础 ASCII）
- P2：滚轮高精度 `factor` 保留（120*factor，Windows factor=delta/WHEEL_DELTA）
- P2：数字小键盘 VK_NUMPAD0-9/运算键 + `EVENTFLAG_IS_KEY_PAD`

### C. 协议层落地 + undo 集成（MVP2 业务核心）【协议规范见《WebUI架构-桥协议与前端SDK.md》】

**现状**：0。架构决策已定（2026-08-03）：传输主通道 = CefViewCore `window.CefViewClient`
（`invokeMethod` 方法调用 + `addEventListener`/`TriggerEvent` 事件），`cefViewQuery` 备用。

**前置验证（2026-08-03 已完成）**：`invokeMethod` 上行全链路可用——JS
`CefViewClient.invoke("scene.create_node", "BridgeNode", 123, true)` → 宿主 `invokeMethodNotify`
收到方法名 + 完整参数（字符串/整数/布尔类型转换正确）。事件下行（TriggerEvent）待 C 项实现时接入。

**设计**（详见架构文档 §3/§4）：
1. C++ `web_bridge` 层：接 `invokeMethodNotify`（方法注册表：`scene.get_node_count` /
   `scene.create_node`(undo) / `editor.undo` / `editor.redo`）+ 事件源（`TriggerEvent`：
   `editor.selection_changed`）；返回统一 `{ ok, result }` / `{ ok:false, error }`
2. `scene.create_node`：经 `EditorUndoRedoManager` 创建 Node3D（可撤销动作，非直接 add_child）
3. `editor.undo/redo`：`EditorUndoRedoManager::undo()/redo()`
4. `scene.get_node_count`：返回 `EditorNode` 当前场景节点数
5. 验证：stub 页面直接调 `window.CefViewClient.invoke(...)`（旧测试页 create_node/undo/count 场景复刻）

**验收**：四个方法全功能 + 撤销/重做有效 + 类型化 SDK 形态可用（sdk 包可在 ui 工程前先行验证）。

## 4. 风险与注意事项

- **桥排障可能触及 thirdparty CefViewCore**（注入缺陷）：优先绕过（宿主侧补注入），避免改 vendored 代码
- **输入转发焦点管理**：面板未聚焦时键盘事件不得转发（CEF 语义），避免误触
- **设备缩放**：`getScreenInfo` 现 device_scale_factor=1.0，坐标映射先按 1:1，后续接 DisplayServer 缩放
- **每帧泵送**（今日修复）已 Win 实测 60fps，mac 复验待排期（共享代码）
- 旧测试页仅参考验收场景，不迁移（其 `sendIpcMessage` API 为 godot-cef 时代，与 CefViewCore 的 `cefViewQuery` 不兼容）
