# 历史优化参考

从 2026-10-21 起，本项目回到官方 Godot 与 GDScript 的开发方式，使用原生节点、场景、资源和编辑器工作流。
先在实际项目中使用引擎，遇到明确的问题或不习惯的地方，再决定是否调整。

本文保存 Misu 以前做过、以后可能用得上的优化，方便遇到类似情况时找到原实现。
这些条目是历史参考，不是待实施计划，也不表示当前官方版本一定存在相同问题。
处理具体需求时，先检查所用版本的原生能力，再参考旧实现做最小调整。

## 历史基线与查阅方式

首次整理时的官方基线是 [6790667243]，来自 `godotengine/godot` 的 `master`，
源码版本标识为 `4.8.beta`。文中的接口和差异以这个时间点为准，后续版本需要重新核对。

检索覆盖作者邮箱相同的 `Misu (米苏)` 与 `mikasomaka` 两种署名，共 396 个非合并提交。
有价值的早期界面改动不全在旧 `master` 中，查阅时需要保留以下两段历史：

| 历史入口 | 提交 | 主要内容 |
| --- | --- | --- |
| [旧 master 备份] | `0e12458135` | 后期 UniGo、外部窗口与 C ABI 改造 |
| [早期编辑器及实验分支备份] | `5620d16d92` | 较早编辑器优化及后续 C#、ECS 等实验 |

条目中的提交链接可以直接查看差异。需要本地查阅时，先获取历史分支，再按提交和文件定位：

```sh
git fetch origin
git show f9fd8fb3b4 -- editor/animation/animation_track_editor.cpp
git show 68965384ca -- editor/inspector/editor_inspector.cpp
```

初次整理时已核对旧提交的实际差异和上述官方基线，但没有在原版编辑器中逐项运行交互回归。
尤其是标题带“修复”的提交，需要分清它修的是官方问题，还是旧 fork 自己引入的问题。
原生设置和局部扩展可参考 [EditorSettings]、[Inspector 插件]、[EditorInterface] 和[官方布局功能]。

## 界面与操作体验参考

### 1. 中文字体、字号与界面缩放

如果中文字体不合适、字号过小或高 DPI 下比例不舒服，可参考 [141a185670]、[68965384ca]、[df33c185c7]。
旧实现统一了编辑器与 WebDock 的字体来源，调整字号、缩放和字体回退，涉及
`editor/themes/editor_fonts.cpp` 与 `editor/settings/editor_settings.cpp`。

原生编辑器已支持自定义字体，可以通过 `interface/editor/fonts/main_font`、`main_font_bold`、
`main_font_size` 及显示缩放设置解决，无需恢复旧字体加载链或 WebDock 同步。
调整后检查中文缺字、粗体、字体缺失回退及不同 DPI；字体路径和显示偏好属于个人环境，不宜全量覆盖他人设置。

### 2. 3D 视口导航偏好

如果不习惯旋转、平移和飞行视角操作，可参考 [26a9abd065]。
旧方案改为右键旋转、中键平移，把飞行视角切换放到鼠标侧键，并增加状态提示。
主要涉及 `editor/scene/3d/node_3d_editor_plugin.cpp`、`editor/settings/editor_settings.cpp`
和 `editor/settings/editor_settings_dialog.cpp`。

先尝试原生 Custom 导航方案、鼠标按钮、修饰键和快捷键设置。
旧提交还移除了右键飞行入口，不只是修改默认值，不能整批移植；
右键旋转与飞行模式激活条件也可能冲突。调整时检查透视/正交视口、旋转/平移/缩放及 `Shift+F`，
保留清楚的进入和退出方式。

### 3. 编辑视口的近远裁剪距离

如果模型特写被裁掉，或远处物体在编辑视口里看不到，可参考 [c47c8beb4f]。
旧改动在 `editor/settings/editor_settings.cpp` 中把 near/far 从 `0.05/4000` 改成 `0.25/400`。

可以通过 `editors/3d/default_z_near` 和 `editors/3d/default_z_far` 设置，无需为此修改源码默认值。
它们只影响编辑视口，不是运行时 `Camera3D` 优化，也没有适合所有项目的固定最佳值。
以后按模型尺寸、观察距离和地图范围选择，并检查设置持久化。

### 4. Inspector 的 Transform 单行编辑

如果 Position、Rotation、Scale 占用空间过多，或 XYZ 排列不方便，可参考 [68965384ca]、[6dcd01e425]。
旧实现让标题与 XYZ 同行，并统一行高和列宽，主要涉及 `editor/inspector/editor_properties.cpp`
和 `editor/inspector/editor_properties_vector.cpp`。

先检查 `interface/inspector/horizontal_vector_types_editing`，它在核对基线中已默认启用，
但不保证完整复现标题同行的旧效果。确有需要时，可用 `EditorInspectorPlugin` 和 `EditorProperty`
仅替换指定属性控件，不必修改 `Node3D` 属性分组、坐标或场景序列化。
需要覆盖撤销重做、多选、动画插关键帧、恢复默认值、只读属性和拖动编辑。

### 5. 紧凑数值输入控件

如果插件工具栏中的数值框太宽、上下箭头挤占空间，可参考 [6dcd01e425]。
旧改动在 `scene/gui/spin_box.cpp` 和 `scene/gui/spin_box.h` 中增加 `SpinBox.show_buttons`，
再用它隐藏吸附输入框的按钮、收窄控件。

核对基线中的原生 `SpinBox` 没有这个属性，不能直接调用旧 API。
以后可先用原生控件与布局组合实现局部输入框，避免只为插件外观修改整个控件类。
调整时注意数值合法性、键盘操作、失焦提交、撤销合并及高 DPI。

### 6. 吸附工具栏的可见性与快捷操作

如果经常修改吸附步长，或需要更方便的对齐操作，可参考 [ceb78feb6f]、[6dcd01e425]。
旧方案把移动、旋转、缩放步长放到工具栏，并拆成三个独立开关。
主要涉及 `editor/scene/3d/node_3d_editor_plugin.cpp` 及其头文件，也涉及多个 Gizmo 和 `scene/3d/node_3d.cpp`。

原提交改了 16 个文件，不是单纯增加输入框。核对基线中的 `EditorInterface` 只公开吸附状态和步长查询，
没有对应的全局设置接口，纯插件不能直接等价接管所有内置 Gizmo 的三个开关。
如果只需快捷对齐，可以对选中节点执行明确的量化命令，或实现自有 Gizmo，
通过 `EditorUndoRedoManager` 支持撤销，并验证局部/世界坐标、父变换和修饰键行为。

### 7. Inspector 分类折叠与状态记忆

如果切换对象后总要重复折叠相同分类，可参考 [68965384ca]。
旧方案增加分类折叠、记忆同名分类状态，并重排节点继承链的展示顺序。
主要涉及 `editor/inspector/editor_inspector.cpp`、对应头文件及 `scene/3d/node_3d.cpp`；
[039fce7e04] 还修复了这套机制首次读取缺省状态的问题。

这套实现新增 `global_folded_paths` 并改变原生属性分组，影响范围较大。
可以先借鉴状态记忆的设计，用于自己的插件面板；是否改造整个原生 Inspector，等实际需求明确后再评估。
缺省状态报错属于旧 fork 自己新增机制的问题，不是官方 Inspector 的独立修复。
验证时覆盖搜索展开、继承场景、多选、收藏属性、项目切换、首次启动及持久化。

### 8. Inspector 行分隔、悬停背景与 Script 区块间距

如果属性层级不清楚、行高不合适，或 Script 区块间距不舒服，可参考
[68965384ca]、[6dcd01e425]、[41787adcc8]。
旧实现调整分隔线、悬停背景、分类标题高度和 Script 区块，涉及 `editor/inspector/editor_inspector.cpp`、
`editor/themes/theme_classic.cpp` 与 `editor/themes/theme_modern.cpp`。

这些视觉规则可用于自有插件控件；改变整个内置 Inspector 的绘制则需要编辑器源码调整。
旧提交还混有隐藏“添加元数据”等入口的改动，不属于当前要保留的方向。
调整外观时检查选中态、键盘焦点、深浅主题、RTL、窄 Inspector 和高 DPI。

### 9. 随工作区隐藏场景标签

如果 Script、Game 等工作区的场景标签容易造成操作误解，可参考 [41787adcc8]。
旧方案只在 2D/3D 工作区显示标签，涉及 `editor/editor_main_screen.cpp`、
`editor/editor_node.cpp` 和 `editor/editor_node.h`。

先结合原生 GDScript 的脚本/场景往返流程判断是否需要隐藏。
旧代码新增了 `EditorNode` 内部可见性刷新机制，尚未核实到稳定的公开标签显隐 API，
不宜通过插件遍历私有控件树强行隐藏。需要检查多场景、游戏工作区、插件主屏和专注模式。

当前已按新版停靠面板结构实现，落地情况与验证结果见[功能优化记录](功能优化记录.md#场景标签按工作区显示)。

### 10. Shader 编辑器获得更大编辑空间

如果 Shader 编辑器挤占 3D 视口或底部工具区，可参考 [d5f5ef1bd0]。
旧实现将内置 `ShaderEditorPlugin` 改成固定主屏标签，调整注册顺序，并移除浮动入口。
相关位置是 `editor/shader/shader_editor_plugin.cpp`、对应头文件、`editor/editor_node.cpp`
和 `editor/register_editor_types.cpp`。

可以先用官方浮动 Shader 编辑器和保存布局解决空间问题。
旧方案需要修改内置编辑器源码，不是能直接启用的 GDScript 插件。
若仍需要固定主屏标签，再评估这一交互取舍，并检查多显示器、单窗口模式、Shader、VisualShader 和布局恢复。

## 缺陷修复线索

### 11. 清空动画时清除残留的导入动画提示

如果从带导入轨道的动画切到空状态后，仍看到上一动画的提示，可参考 [f9fd8fb3b4]。
旧补丁只在 `editor/animation/animation_track_editor.cpp` 的 `AnimationTrackEditor::set_animation()`
无效动画分支中增加 `imported_anim_warning->hide()`。

核对基线中仍有这处差异，但尚未在原版 GUI 中复现。
以后遇到时，可先检查这处 UI 状态清理；确认后再决定本地调整或向官方提交。
修复应保留有效导入动画本来需要的警告，并验证导入动画切到空状态、切到普通动画及关闭动画库等路径。

### 12. Windows 外部编辑器 PATH/PATHEXT 与脚本启动

如果外部编辑器配置 `code` 等命令时无法启动，可参考 [039fce7e04]、[a095555293]。
旧实现修改 `platform/windows/os_windows.cpp` 的 `OS_Windows::create_process()`，
通过 `PATH`、`PATHEXT` 查找命令，并为 `.cmd`、`.bat` 增加命令解释器启动路径。

先尝试填写外部编辑器可执行文件的绝对路径。
旧补丁影响所有子进程，涉及命令解释器的引号、参数和特殊字符处理，不能当作局部 UI 修复直接搬回。
确需调整时，检查空格、中文、引号、特殊字符、扩展名、`PATHEXT` 顺序及参数传递。
历史提交还混有其他改动，应按文件和实际差异提取；初次整理没有运行平台回归。

## 工程工具参考

### 13. 跨平台构建入口与安装任务

如果以后需要从源码构建官方引擎，可参考 [92db893868]、[e836a060ae]。
旧方案用 `Taskfile.yml` 和 `misc/scripts/build.py` 统一 Windows/macOS 构建入口，
并增加 macOS 编辑器安装任务。

可以借鉴任务编排、退出码处理和安装流程，不恢复旧的 UniGo、3D 裁剪或 Mono 构建预设。
直接使用官方预编译编辑器时，无需先恢复这套工具链。
使用前按当时的官方构建要求核对参数，并验证空格路径、平台差异和失败退出码。

### 14. 本地分析缓存忽略

如果 `.codegraph` 等缓存经常出现在未跟踪文件中，可参考 [bd2ec45289]、[53e99313fa]。
旧改动只是在 `.gitignore` 中增加本地缓存规则。

个人缓存可以放到 `.git/info/exclude` 或个人 Git ignore，避免为本机工具增加公共仓库改动。
不要机械复制旧测试项目的全部忽略规则，尤其要确认应跟踪的资源标识文件没有被一起排除。

## 不沿用的旧架构与相关修复

以下历史保留供查阅，不作为当前原生 Godot + GDScript 的迁移方向：

| 历史内容 | 不沿用的原因 |
| --- | --- |
| UniGo、C ABI、外部 HWND、纯渲染内核、无场景/无项目启动 | 服务于把 Godot 作为其他宿主的内核，已改变开发方式 |
| C#/.NET、NuGet、禁用 GDScript、ECS、Object+Components、自定义场景格式 | 与原生节点、场景和 GDScript 工作流不一致 |
| CEF/WebDock、Electron、Avalonia 等编辑器替代方案 | 不再建设另一套编辑器或浏览器宿主 |
| 坐标系、投影、相机前向、渲染语义和 String 智能解码 | 改变核心约定，相关修复可能只服务于旧改造 |
| EasyBoneMap、品牌替换 | 独立新增工具或品牌内容，不属于本次通用优化参考 |

还需避免把宿主相关修复误判为官方缺陷：

- [1c9c4914d0] 的实际差异含 `external_window_mode` 尺寸同步，不能只按标题判断为原生窗口缩放修复。
- [b45ad072fd] 的退出确认焦点修复只改自定义 `modules/att_webview/webview_manager.cpp`。
- [fa01ed166f] 等光标补丁含 fork 专属依赖，需先在官方版本中复现，不能直接沿用旧根因判断。
- 第 7 节提到的 Inspector 缺省状态报错，属于旧 fork 新增折叠机制的问题。

## 以后遇到问题时如何使用本文

先记录所用 Godot 版本、具体操作和预期行为，在原生流程中确认问题是否存在。
如果是操作偏好，先检查原生设置或布局；确实需要修改时，再找到本文对应条目，查看旧提交的实际差异。
混合提交应按需求提取相关部分，不把旧宿主、核心约定或功能删减一并带回。

本地改动需要覆盖实际触发路径及受影响的原生功能。可独立成立的通用缺陷可以考虑向官方提交；
如果后续版本已经解决，也应在这里补记版本和结论，方便下次查阅。
新增确认有价值的使用经验时，再持续补充本目录。
