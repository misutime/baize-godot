# 3D 动画资源规范

骨骼动画工具由定制引擎直接提供。新项目无需复制插件或修改 project.godot。开发资产统一使用 Godot 原生文本序列化，扩展名表示资产职责。

| 资产 | 原生类型与内容 | 保存规则 |
| --- | --- | --- |
| .sk | SkeletonDefinition，骨骼名称、父子关系、局部 Rest、动画目录名、默认预览模型 | 文本资源，不列出片段；片段来自动画目录下的 .skanim 文件 |
| .skanim | Animation，单个片段的轨道、关键帧、时长、循环和骨骼关联 | 独立文本资源，剪辑写回原文件 |
| .skmesh | PackedScene，模型、Mesh、Skin、Skeleton3D 和动画节点 | 文本场景，网格和蒙皮继续内嵌 |
| .animtree | AnimationRootNode，独立共享的 BlendTree 或状态机 | 文本资源，节点通过 Tree Root 引用 |

文件系统、快速打开和中央标签为这四种资产使用统一的骨骼动画资产图标族，以扩展名区分，不改变其底层资源类型。

文本 SKMesh 中的顶点、索引及权重可能是较大的编码数组。模型结构、引用和动画逻辑可以直接查看，几何修改通过建模工具及“从文件更新 SKMesh”完成。

每份 .sk 是一份明确的骨骼定义，骨名、层级和 Rest 用于导入校验。它不列出任何片段，只保存动画目录名 `animation_directory`（相对 .sk 所在目录，默认 `<骨骼名>_anims`）。该目录下的 .skanim 文件就是这份骨骼的全部动画：目录根下的文件属于默认动画库，一层子目录是以目录名命名的动画库。新增动画就是往目录里放一个 .skanim，所有关联模型的 AnimationPlayer 自动获得它。AI 直接创建片段时，把文件保存到动画目录并让片段引用所属骨骼即可，不需要修改 .sk。

动画名是运行时 API：`AnimationPlayer.play("Run")`、autoplay、下一段动画、混合时间、AnimationTree 的动画节点和嵌套动画轨道都通过名称查找。动画名就是 .skanim 的文件名，位于子目录时为“目录名/文件名”，没有第二份名称或分类元数据。因此重命名或移动片段文件会改变动画名，按旧名引用的脚本和动画图不会自动更新；动画图中引用不存在动画的节点显示为红色。文件名不能包含 `/`、`:`、`,`、`[`，这类文件不会被加载，并在工作台的“Needs Attention”分组中报告。

`.skanim` 是骨骼动画目录中的文件，不拥有独立中央文档。双击片段会打开或激活所属 `.sk` 并选中对应条目。片段必须引用已保存的 `.sk`，导入、另存和保存 `.skanim` 时都会校验；这份引用只做安全校验，不决定动画名。空关联、失效关联、或文件不在所属骨骼动画目录里的片段会进入重新绑定流程：选择已有 `.sk`、提供动画名并验证片段使用的骨骼仍然存在，确认后文件被移入该骨骼的动画目录。动画目录里引用了其他骨骼的片段不会被加载。

绑定 `skeleton_definition` 的 AnimationPlayer 的全部动画库都由 `.sk` 派生，与骨骼动画目录的结构一一对应。这些库不会序列化进 `.skmesh`，播放器也不能自行添加、删除或重命名动画库，避免一个模型出现第二份骨骼动画来源。解除骨骼绑定后，播放器恢复普通原生 AnimationPlayer 行为。SKMesh 的模型局部内容如果需要独立动画，应使用明确的独立资产，不应把另一个库藏进骨骼播放器。导出的游戏不扫描目录：导出时扫描结果被写入包内 `.sk` 的 `animation_libraries`。

AnimationPlayer.skeleton_definition 是模型的骨骼绑定入口。新生成的 SKMesh 包含同级的 Skeleton3D、Meshes 和 AnimationPlayer，播放器的 Root Node 指向 SKMesh 根节点。骨骼轨道使用 `Skeleton3D:骨名`，网格轨道使用 `Meshes/网格名:属性`。

Animation 中的骨骼 UID 与备用路径用于资产关联和直接预览，采用软引用以避免骨骼目录与片段之间循环加载。SKMesh 中的播放器直接引用 .sk，提供运行时依赖。骨骼的默认预览模型同样使用软引用，预览模型不会因为加载骨骼而自动加载。

角色场景负责动画控制。把 AnimationTree 与 SKMesh 模型实例放在角色节点下，将动画树的 Anim Player 设为模型实例内部的 AnimationPlayer。动画树沿用该播放器的 Root Node，片段轨道继续相对 SKMesh 根节点解析。多个角色共用动画逻辑时，可以保存为独立 `.animtree`。共享图记录目标骨骼，绑定时校验骨骼身份。各 AnimationTree 分别保存运行参数、播放进度和状态机状态。

动画图的存储操作在节点检查器及中央标签中提供。选择共享图会更新节点引用，保存为共享图会生成文件并自动绑定，转为内嵌副本会给当前节点创建自己的图。引用操作是普通的场景修改，进入场景撤销历史，随场景保存落盘。内嵌图内容使用场景撤销历史及场景保存，独立图内容使用文档工作副本及文件保存。

片段内容修改使用内存草稿，支持连续删除、撤销、重做和保存检查点。Ctrl+S 写回原 .skanim 并保持 AnimationPlayer 引用，保存后撤销只改变内存结果，再次保存才写入磁盘。另存新片段生成 .skanim 并登记到骨骼目录。

导入器记录实际采样 FPS，工作区据此计算帧数和选区吸附。缺少该记录时使用 Animation.step，不能确定时使用秒。开发片段保留未压缩的可编辑轨道。

普通场景保存只保存当前组织。新资产的创建、片段登记和动画图外置通过明确操作完成。旧版 `.sk` 的内嵌动画库仍可读取，可以在工作台迁移至动画目录，也会在向该骨骼写入新片段前迁移。更新 SKMesh 只更新模型。片段使用独立后缀 `.skanim`，Godot 原生的二进制 `.anim`、通用 `.tres`／`.res` 和原生场景导入继续使用原生资源机制。

资源类型和共享库逻辑位于 scene/resources 与 scene/animation。中央片段工作区、时间轴、预览和导入窗口位于 editor/animation/animation_workbench_editor_plugin.*，动画树中央编辑与共享操作位于 animation_tree_editor_plugin.*。编辑器 UI 和文件规则均随引擎分发。
