# 3D 动画资源规范

骨骼动画工具由定制引擎直接提供。新项目无需复制插件或修改 project.godot。开发资产统一使用 Godot 原生文本序列化，扩展名表示资产职责。

| 资产 | 原生类型与内容 | 保存规则 |
| --- | --- | --- |
| .sk | SkeletonDefinition，骨骼名称、父子关系、局部 Rest、共享动画目录、默认预览模型 | 文本资源，共享目录内嵌，片段使用外部引用 |
| .anim | Animation，单个片段的轨道、关键帧、时长、循环和骨骼关联 | 独立文本资源，剪辑写回原文件 |
| .skmesh | PackedScene，模型、Mesh、Skin、Skeleton3D 和动画节点 | 文本场景，网格和蒙皮继续内嵌 |
| .animtree | AnimationRootNode，独立共享的 BlendTree 或状态机 | 文本资源，节点通过 Tree Root 引用 |

文本 SKMesh 中的顶点、索引及权重可能是较大的编码数组。模型结构、引用和动画逻辑可以直接查看，几何修改通过建模工具及“从文件更新 SKMesh”完成。

每份 .sk 是一份明确的骨骼定义，骨名、层级和 Rest 用于导入校验。共享 AnimationLibrary 是其中的动画目录，只引用独立 .anim。新增动画通过导入服务登记到目录，所有关联模型的 AnimationPlayer 自动获得这些动画。AI 直接创建片段时，也需要更新所属骨骼的目录引用。

AnimationPlayer.skeleton_definition 是模型的骨骼绑定入口。SKMesh 中 Skeleton3D、Meshes、AnimationPlayer 和 AnimationTree 同级；播放器和动画树的 Root Node 指向父节点，AnimationTree 的 Anim Player 指向同级 AnimationPlayer。骨骼轨道使用 Skeleton3D:骨名，网格轨道使用 Meshes/网格名:属性。

Animation 中的骨骼 UID 与备用路径用于资产关联和直接预览，采用软引用以避免骨骼目录与片段之间循环加载。SKMesh 中的播放器直接引用 .sk，提供运行时依赖。骨骼的默认预览模型同样使用软引用，预览模型不会因为加载骨骼而自动加载。

动画图默认内嵌在 SKMesh 中，新模型使用只有 Output 的 BlendTree，Active 关闭。多个模型共用动画逻辑时，可以保存为独立 .animtree。共享图记录目标骨骼，绑定时校验骨骼身份。各 AnimationTree 共用图结构，分别保存运行参数、播放进度和状态机状态。

动画图的存储操作在节点检查器及中央标签中提供。选择共享图会更新节点引用，保存为共享图会生成文件并自动绑定，转为内嵌副本会给当前节点创建自己的图。引用操作即时保存所属场景，并进入场景撤销历史。内嵌图内容使用场景撤销历史及场景保存，独立图内容使用文档工作副本及文件保存。

片段内容修改使用内存草稿，支持连续删除、撤销、重做和保存检查点。Ctrl+S 写回原 .anim 并保持 AnimationPlayer 引用，保存后撤销只改变内存结果，再次保存才写入磁盘。另存新片段生成 .anim 并登记到骨骼目录。

导入器记录实际采样 FPS，工作区据此计算帧数和选区吸附。缺少该记录时使用 Animation.step，不能确定时使用秒。开发片段保留未压缩的可编辑轨道。

普通场景保存只保存当前组织。新资产的创建、片段登记和动画图外置通过明确操作完成。原型中的 .skeleton／.animlib 后缀、二进制 .anim／.skmesh、来源身份、自动拆库和迁移逻辑已移除。Godot 的通用 .tres／.res 和原生场景导入继续使用原生资源机制。

资源类型和共享库逻辑位于 scene/resources 与 scene/animation。中央片段工作区、时间轴、预览和导入窗口位于 editor/animation/animation_workbench_editor_plugin.*，动画树中央编辑与共享操作位于 animation_tree_editor_plugin.*。编辑器 UI 和文件规则均随引擎分发。
