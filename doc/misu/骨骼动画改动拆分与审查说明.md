# 骨骼动画改动拆分与审查说明

建议拆成三个按依赖顺序合并的 PR。第一项交付中央文档和脚本工作区，第二项交付骨骼动画从导入到打包的完整流程，第三项交付主 3D 视口与动画预览的共享导航。中央文档可以用普通场景和脚本独立使用，共享导航也有独立的原生交互验证范围。骨骼资源、导入、编辑、动画图和导出共用资产约定，应在同一项里走完整流程。

拆分基线为仓库远端 master 的 bfe773a475，本地已提交版本为 d14d8a0f24，范围同时包含当前工作区和两个尚未跟踪的 editor_3d_navigation 源文件。现有 [PR #25](https://github.com/misutime/baize-godot/pull/25) 保留为草稿和历史入口。拆分分支准备好后，第一项以远端 master 为目标，第二项起初以第一项分支为目标，第三项起初以第二项分支为目标。每次前置 PR 合并后，将后续项移到最新 master 上并重新核对其独有 diff。#25 的替代关系等三个分支就位后再登记。

PR 数量只影响审查边界。后续跟进 Godot 上游时，冲突范围取决于实际改到的原生代码。宿主只处理文档生命周期，骨骼细节留在动画资源、导入和编辑器模块，导航配置与输入留在共享导航模块。涉及原生加载、场景树、视口和打包的接入点应能用一个具体用例解释，并在对应 PR 的说明中列出。审查时以同一上游基线检查这些改动，优先关注双方都改过的函数。若能用已有回调接入、把决策挪到自定义模块或去掉无关整理，请把预计能缩小的原生改动列出来。

## PR 1 中央文档和脚本工作区

**建议标题**　统一中央文档标签与编辑器上下文

将场景和脚本纳入同一个中央文档宿主。负责标签固定、排序、滚动、关闭和布局恢复，管理文档切换时的场景树、检查器、选择、滚动位置与撤销历史。包括场景锁定、脚本容器生命周期、通用 TabBar 接入及脚本编辑位置恢复。以普通场景、脚本和测试用资源文档作为本 PR 的验证对象。

请从空项目创建两个场景，各挂一个脚本。交替打开场景、脚本和测试用资源文档，编辑后切换、关闭、选择保存或取消，再重新打开编辑器。检查标签与未保存标记、固定后的关闭行为、横向滚动、脚本光标／历史／滚动位置，以及恢复后焦点是否落在用户预期的位置。再锁定场景 A，切到场景 B，检查锁定面板的查看和编辑边界，解锁后确认检查器、选中节点和撤销归属。用原生 2D、3D、脚本编辑、快捷键与调试跳转路径各走一次，记录普通项目新增的操作成本和功能缺口。

请评估文档提供方与标签宿主的接口是否足够小，活动文档、锁定上下文和各场景状态是否各有明确的所有者。若可减少重复恢复、焦点补偿或散落的原生入口，请给出可以保留上述操作流程的具体重构方案。在仓库根目录运行 `python misc/misu/document_context_regression/run.py --godot <本项构建的编辑器可执行文件>`。

## PR 2 骨骼动画资产工作流

**建议标题**　内置骨骼动画资产的导入、编辑与导出

在中央文档宿主上交付骨骼动画全流程。包括 SkeletonDefinition 和四种文本资产、目录派生动画库与旧资产兼容、GLB 导入和采样率、模型更新、工作台、内嵌与共享动画图、所选场景打包、资产图标及配套文档。工作台保留可独立使用的预览导航，PR 3 再接入共享导航。

请在空项目导入带骨骼的 GLB，创建模型和首批片段，再导入同骨骼的第二个模型及仅动画 GLB。检查自动匹配、手动选骨骼、采样率和失败提示是否足够清楚。按普通用户操作，在文件系统打开片段，在工作台中搜索、改名、移动、定位，处理孤儿或错误骨骼片段；同时检查外部改名、旧库迁移、重名、只读路径和失败回滚时的状态。在预览中用帧和秒各做一次区间剪辑，覆盖单帧、端点、连续剪辑、撤销、保存、重新加载和另存。记录常用操作的入口是否容易找到，预览播放、片段循环、持久化与让旧动画名失效的行为是否能从界面理解。

请在角色场景实例化两个 SKMesh，用 AnimationTree 绑定目标实例，分别尝试内嵌图、共享图和还原内嵌，检查绑定、撤销、保存和再次打开时的行为。更新已有 SKMesh，再按所选场景及依赖导出 PCK 并运行，核对保留的骨骼、网格、播放器、动画树、命名库和动画片段，以及无关资源的排除。补查常规 GLB 导入、原生二进制 .anim、未绑定骨骼的播放器及原生 2D 动画编辑。

请评估资产的所有权、名称和 UID 规则是否易懂，编辑器目录扫描与包内烘焙是否遵守同一套资产约定，工作台的预览、剪辑、文件操作与保存能否用更少的共享状态表达。若改动触及通用文本加载、导入器、SpinBox 或场景树，请核对是否能把资产特有逻辑留在专用模块，并写明简化前后对具体操作和旧项目的影响。在仓库根目录运行 `python misc/misu/animation_regression/run.py --godot <本项构建的编辑器可执行文件>`，其中包含所选场景的导出检查。

## PR 3 共用 3D 视口导航

**建议标题**　统一主 3D 视口与动画预览的导航输入

把主 3D 视口和动画预览的共用导航设置、鼠标键与修饰键处理集中到 Editor3DNavigation。一起纳入 View3DController 的相应初始化、两个调用点和预览专属的相机呈现调整。SKMesh 首次打开时的模型聚焦随资产行为放在 PR 2。

请在普通 3D 场景和动画预览中都操作旋转、平移、缩放、聚焦和自由视角，覆盖默认与自定义鼠标键及修饰键设置。切换标签或窗口焦点，检查相机状态和输入释放；在主视口补查选取、右键菜单、变换操作和相机预览，在动画工作台补查预览输入和时间轴操作是否互相影响。记录原生路径与前置版本的差异，评估共享层是否只包含两处共用的行为，以及视口专用规则是否仍在调用端。涉及真实鼠标、焦点和视角的结论应来自图形界面操作。
