## 2026-11-12

### 活动文档上下文与场景锁定

中央标签接入资源文档后，场景树、检查器、信号和分组面板仍停留在上一个场景，容易对着资源文档误操作场景节点。本 fork 让这些面板跟随当前活动文档：场景标签显示各自的场景，带节点的文档显示所属场景，没有场景对象的资源文档显示“无场景上下文”占位。每个文档保存自己的检查对象、选择、编辑历史和两个面板的滚动位置，切回时恢复。标签栏右侧的锁定按钮可以把这些面板固定在当前场景上，之后切换到其他场景或资源文档只改变中央工作区。

后续审查修复了以下问题。已有资源文档激活或上下文锁定时，从文件系统打开另一个 `.sk`、`.skanim` 不再被拦截，仍会打开或切换到对应文档。锁定期间编辑锁定场景的节点，撤销历史归入该场景，而不是全局历史。保存的上下文改为按场景根对象识别场景，关闭其他场景后序号变化不再影响恢复。解锁时恢复当前文档自己的编辑历史。文档提供方在编辑器销毁阶段移除标签时不再激活相邻文档，脚本直接退出不会崩溃。动画预览的播放开关在切换标签、区间删除、撤销、重做和保存后保持不变，只有“重置 Pose”、拖动时间轴和定位会暂停。

锁定的场景不是当前编辑场景时，它的节点不在场景树内，此时场景树面板和检查器为只读：新建、实例化、重命名、拖动重排和属性修改都被禁用，锁定按钮的提示会说明这一点。切回锁定的场景或解锁后恢复可编辑。信号和分组面板没有单独禁用。

实现位于 `editor/editor_node.*`、`editor/editor_undo_redo_manager.cpp`、`editor/scene/editor_scene_tabs.*`、`editor/docks/scene_tree_dock.*` 和 `editor/animation/animation_workbench_editor_plugin.*`。验证：Windows 增量构建通过；骨骼动画回归集 28/28、文档上下文回归集 8/8 通过，新增场景覆盖文档激活时打开其他资源、离开工作台和编辑后保持播放、锁定时打开资源文档与历史归属、文档激活状态下退出。标签滚动、真实鼠标关闭和拖动排序仍需图形界面验证。

### 骨骼动画资产使用独立图标族

`.sk`、`.skanim`、`.skmesh` 和 `.animtree` 虽然分别映射到 `SkeletonDefinition`、`Animation`、`PackedScene` 和动画图资源，但文件系统此前只按基础资源类型取图标。结果是 `.sk` 落到通用资源图标，`.skanim` 与普通 Animation 相同，`.skmesh` 与普通场景相同，中央标签也存在按节点或按基础类型临时取图标的情况。

本 fork 建立 `SKSkeleton`、`SKAnimation`、`SKMesh` 和 `SKAnimationTree` 四个资产图标，并通过统一的扩展名映射供文件系统、快速打开和中央标签共用。骨骼使用红色骨架，动画片段使用紫色循环标识，骨骼模型使用蓝色网格与骨骼节点，动画图使用绿色图结构；普通 `.tscn`、`.tres`、`.anim` 等原生资源仍使用原有图标。资源类型本身不变，避免影响加载、保存和场景流程。

映射入口位于 `editor/editor_node.cpp` 的 `get_custom_resource_file_icon()`，图标资源位于 `editor/icons/`，文件系统、快速打开、动画工作台、动画树和场景标签统一复用该入口。Windows 增量构建通过，骨骼动画回归集 24/24、文档上下文回归集 8/8；实机确认资产族图标在文件系统和中央标签中一致显示。

### 动画预览播放状态改为全局保持

动画工作台此前虽然把播放开关保存在插件实例中，但每次打开新的 `.skanim` 文件都会先销毁旧预览。销毁路径调用了暂停，导致从右侧列表切换片段时保留播放，而从文件系统打开新片段时却回到暂停状态。

本 fork 将播放开关明确视为工作台全局状态。重建预览或离开动画工作台只停止旧预览实例，不再改写播放意图；新文档建立预览后沿用原开关，播放状态下打开的下一个片段会继续播放，暂停状态下也不会自动开始。预览循环、倍速和播放时间仍按原有规则处理。

实现位于 `editor/animation/animation_workbench_editor_plugin.cpp`。骨骼动画回归集新增“连续打开不同片段文件后仍保持播放”的场景，当前 23/23 项通过。

### 明确标记未保存的中央文档

动画片段复用单一工作台标签后，切换片段不会打断当前操作，多个片段的草稿可以同时保留在内存中。但仅靠共享标签原有的修改标记，无法在切换到片段 B 后看出片段 A 尚未保存；长片段名也会让名称末尾的星号容易被截断，而且不同文档类型此前使用不同的标记位置。

本 fork 保留快捷切换和多草稿行为，并将未保存标记统一到所有中央标签：场景、脚本、动画树、骨骼和共享动画片段存在修改时，标题统一为 `* 名称`，星号位于图标与名称之间，不再使用末尾 `(*)`。右侧动画片段列表也在对应名称前显示 `*`，tooltip 说明该片段有未保存修改；共享标签 tooltip 列出所有未保存片段。保存、撤销回保存点或恢复草稿后，标签和列表标记同步消失。关闭共享标签时仍统一提示保存、放弃或取消。

实现位于 `editor/animation/animation_workbench_editor_plugin.cpp` 和 `editor/scene/editor_scene_tabs.cpp`。骨骼动画回归集新增动画片段与场景标签的前置标记检查，并验证撤销／保存后标记清除，当前 23/23 项通过。

### 动画片段复用单一中央标签

动画工作台此前为每个 `.skanim` 创建一个中央标签。模型片段通常有几十个，标签栏很快被同类型的动画资源占满；这些标签又共享完全相同的预览、时间轴和片段切换逻辑，单独占位没有带来额外操作能力。

本 fork 将动画片段改为类似脚本文档容器的单一工作台标签。第一次打开 `.skanim` 时创建一个动画片段工作台标签，标题为当前片段名；之后打开其他片段会复用该标签并更新标题，不再新增中央标签。工作台内部仍按片段保留文档、草稿和撤销历史，修改状态聚合到共享标签；保存共享标签会保存所有已修改片段，关闭时统一确认未保存内容。关闭标签只隐藏工作台，重新打开片段会恢复共享容器。编辑器布局额外记录最后激活的片段路径，启动恢复时仍能回到对应内容。`.sk` 骨骼资产和场景 `AnimationPlayer` 的独立标签行为保持不变。

实现位于 `editor/animation/animation_workbench_editor_plugin.*` 和 `editor/scene/editor_scene_tabs.*`。`EditorSceneTabs` 增加标题更新和布局恢复提示，标签身份与当前片段路径分离。验证使用 12 个连续打开的 `.skanim`：中央标签总数从 14 降为 3，仅剩场景、脚本和一个动画片段标签，标题停在最后打开的片段；关闭该标签后重新双击片段 05，会重新创建一个共享标签。骨骼动画回归集新增片段标签复用场景并通过 23/23 项。详细交互见[编辑器文档标签](编辑器文档标签.md)和[骨骼资源与动画资产工作流](骨骼资源与动画资产工作流.md)。

### 中央文档标签改为连续横向滚动

原生 `TabBar` 在标签超出可用宽度后隐藏其余标签，只通过右侧左右箭头按内部偏移切换。随着本 fork 接入骨骼、动画片段、动画树和脚本等更多文档类型，标签数量经常超过可视范围；箭头模式既无法露出部分标签，也不容易看出后面还有多少内容。

本 fork 保留原生 `TabBar` 的标签绘制、拖动排序、固定、关闭和事件处理，只在其外层增加横向 `ScrollContainer`。标签栏设置 `clip_tabs=false` 后按全部标签的真实宽度展开，由滚动容器按像素裁剪和移动，因此可以显示三个半之类的连续内容；横向滚动条、鼠标滚轮和触控板都用于平移，不再使用左右箭头。新建场景、已打开场景列表和额外固定按钮放在滚动区外，滚动时保持位置不变。当前文档变化、从场景列表选择隐藏标签和窗口尺寸变化时，只按最小距离把目标标签滚入视野，不会因滚动本身切换当前文档。

改动仅涉及 `editor/scene/editor_scene_tabs.cpp` 和 `editor/scene/editor_scene_tabs.h`，没有修改 `TabBar` 或 `ScrollContainer` 的公共行为，影响范围限于中央文档标签栏。详细交互说明见[编辑器文档标签](编辑器文档标签.md)。

验证使用包含 14 个打开文档的 Windows 编辑器测试项目 `bin/misu/tab-scroll-check`：完整内容宽度约为 5699 像素、可视宽度约为 1813 像素，滚动范围为 0～3886 像素；实测拖动滚动条可连续平移，滚轮可横向滚动，边缘显示部分标签，右侧固定按钮保持可见，从场景列表切回首尾标签会自动滚入视野，滚动状态下右键菜单位置正确。Windows 增量构建通过，骨骼动画原生回归集 23/23 场景通过。

## 2026-10-24

### 动画编辑器预览控制与时间显示

动画编辑器现在将预览循环和倍率与运行配置分离，方便反复观察单次动作。移除工具栏的自动播放按钮及列表标记，保留运行时 autoplay API 和已有场景配置。开始预览后始终按当前有效时长或标记区间线性循环，支持正播和倒播；资源的 loop_mode 不被改写，游戏运行仍遵循原配置。

播放位置右侧新增 0.5×、1×、2× 和自定义倍率，自定义范围为 0.01×～100×。倍率只控制编辑器预览，不修改节点 speed_scale，也不重置位置或播放状态；会话内切换动画和播放器后保留所选倍率。预览使用独立实例状态，不序列化到场景。

空格切换播放和暂停，倒播暂停后按原方向恢复；切换动画保持原来的播放／暂停状态。动画面板和 3D 编辑器拥有焦点时均可使用，文本输入不受影响，解决完整动画菜单关闭后焦点回到 3D 视口导致空格失效的问题。3D 悬停仍沿用原生行为。动画面板可见且存在可播放动画时，空格优先控制预览，会占用 3D 的空格最大化视口和数值变换确认，变换可用回车确认。时间线保留中键平移，改绑预览快捷键后仍可使用原生空格平移。

时间轴、动画长度、原始／基准时长和当前位置统一跟随“秒／帧”选项切换。帧数按 Animation.step 换算，与预览倍率及实际渲染帧率无关；步长框明确显示 FPS 或秒后缀。帧模式的位置框显示、输入整数帧，箭头一次增减一帧，并增加宽度避免前导数字被截断；秒模式保留四位小数。内部时间保持连续，切换单位不改变姿势、播放状态或资源数据；FPS 为零时位置、长度和参考值回退到秒。

普通拖动截止手柄只查看姿势，按住 Command/Ctrl 开始拖动才修改长度；拖动期间该修饰键不反转吸附，Shift 精细吸附、撤销／重做和右键取消保留，只读动画不可修改。时长旁新增只读参考值：新导入动画及切片记录“原始”时长，旧资源或手工动画在首次面板长度修改时保存“基准”。参考值随动画保存，连续输入长度后撤销／重做也能正确恢复；未记录的历史裁剪无法据此还原。截止线提示只在手柄上显示，并修正手柄定位及长度控件布局。

预览覆盖在播放器由面板编辑期间生效，包含这期间由工具脚本触发的播放；需要在编辑器中依赖 animation_finished 的脚本应注意这一语义。原始时长指当前导入片段的长度，不是整个 DCC 文件的时间轴；时长参考元数据随资源导出。

实现位于 `editor/animation/animation_player_editor_plugin.*`、`animation_track_editor.*`、`editor/import/3d/resource_importer_scene.cpp`、`scene/animation/animation_player.*` 及简体中文编辑器翻译。
Windows 构建、原生冒烟、112 项图形编辑器集成检查和 8 项运行时检查通过，覆盖循环、速度隔离、切换状态、3D 焦点下空格、单位换算、整数帧显示、倒播恢复和合并撤销。最终测试日志未发现 ERROR、SCRIPT ERROR 或 WARNING；尚未验证 macOS Cmd 手势、非工具导出模板及全部轨道类型。

## 2026-11-12

### 骨骼动画目录分类与来源约束

动画目录此前只有名称和片段引用，动画数量增加后缺少稳定组织方式；同时绑定骨骼的 AnimationPlayer 在编辑器里仍可能被挂接额外的动画库，形成第二份骨骼动画来源。

本 fork 在 `.sk` 内增加按片段稳定身份（资源 UID，缺失时回退路径）保存的分类与标签元数据。动画工作台按分类分组显示片段，并新增“Animation Catalog”管理窗口，展示名称、分类、标签、源文件、稳定身份和骨骼归属，支持修改分类与标签。分类只属于编辑器组织信息，不改变 `AnimationPlayer.play()` 使用的动画名；修改已打开 `.sk` 时进入文档未保存状态，关闭时支持保存或放弃。没有打开 `.sk` 文档时，管理窗口直接保存目录。

绑定 `skeleton_definition` 的 AnimationPlayer 现在只保留由骨骼派生的默认库，新增、删除和重命名其他动画库会被拒绝；设置骨骼时也会清理旧库。AnimationTree 的临时预览播放器在骨骼绑定时直接使用派生目录，不再复制库。解除骨骼绑定后恢复原生播放器行为。

实现位于 `scene/resources/skeleton_definition.*`、`scene/animation/animation_mixer.*`、`scene/animation/animation_player.*`、`editor/animation/animation_workbench_editor_plugin.*` 和 `editor/animation/animation_tree_editor_plugin.cpp`。动画回归扩展了分类持久化、身份稳定性和额外库拒绝场景。

### SKAnim 归属骨骼文档与孤儿修复

`.skanim` 此前拥有全局共享的片段标签，但它没有独立的动画名，目录名称、分类、预览模型和兄弟片段都来自所属 `.sk`，独立文档身份容易造成上下文歧义。

现在双击 `.skanim` 会打开或激活所属 `.sk` 文档，并在动画目录中选中对应片段；标签身份保存在骨骼文档，片段只作为目录条目和内部草稿切换。编辑器布局恢复记录每个骨骼最后打开的片段。未关联骨骼、关联失效或未登记到目录的片段会弹出重新绑定对话框，要求选择已有 `.sk`、填写目录名称并校验片段使用的骨骼仍然存在。

`.skanim` 的文本保存层现在强制要求资源引用已保存的 `.sk`，导入、另存和普通保存都会经过该校验。重新绑定先写入骨骼目录再保存片段，失败时恢复原关联和目录状态。回归覆盖所属骨骼标签路由、孤儿检测、重新绑定和未绑定片段保存拒绝。

原共享片段标签专用的 `editor://animation_clips` 工作区、片段标签保存／关闭回调和按标签聚合状态已删除。骨骼标签把最后选中的 `.skanim` 保存为布局恢复路径，启动时重新路由到所属 `.sk` 并选中片段；这是当前布局恢复机制，不承担旧项目资产迁移。未保存片段现在直接聚合到对应骨骼标签的修改状态和 tooltip。

## 2026-11-13 动画目录成为骨骼动画的唯一来源

原结论（2026-11-12）：`.sk` 内嵌的 AnimationLibrary 是唯一动画目录，分类和标签作为不影响运行时名称的编辑器元数据存在 `.sk` 的 `animation_metadata` 里。

为什么改：片段同时有文件名、`resource_name`、库内键名三个名字，播放只认第三个，改文件名不影响它；分类又是第四份组织信息，还需要按 UID 清理失效条目。来源不唯一，改名时总要考虑另一处是否同步。

新结论：`.sk` 只保存动画目录名，运行时和编辑器都通过扫描该目录得到动画库（根目录为默认库，一层子目录为命名库），文件名即动画名。分类、标签及其管理界面删除。绑定骨骼的 AnimationPlayer 从“只有一个派生默认库”放宽为“所有库都派生自骨骼”。导出时由导出插件把扫描结果烘焙进包内 `.sk`。旧版内嵌列表仍可加载，并提供一次性迁移。

改名或移动会改变脚本和动画图使用的动画名，原引用需要手动更新。动画图会标出引用了缺失片段的节点。按所选场景导出时，引擎在收集依赖阶段纳入骨骼目录下的片段，再生成包内动画库。详见[骨骼资源与动画资产工作流](骨骼资源与动画资产工作流.md)。
