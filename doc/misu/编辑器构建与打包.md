# 编辑器构建与打包

这套入口构建 Windows x86_64 原生 Godot 编辑器，保留官方默认模块和 GDScript，明确关闭 Mono/C#。
目标是与同一上游版本的标准版保持功能一致，不要求复刻官方发行包的编译器、优化或调试信息参数。
本地构建、冒烟验证和生成便携 ZIP 可以用一个命令完成，适合以后修改引擎时重复执行。
脚本位于 `misc/misu/build_windows.py`，构建过程仍由官方 SCons 驱动，不修改引擎源码或模块白名单。

## 从旧开发中保留的经验

历史提交 [92db893868] 的 Python 入口、任务编排和错误退出处理可以复用，
但旧脚本指向专用的 3D 裁剪预设，不能直接恢复。这里用一份 Windows 入口明确平台和目标，
不再引入旧的 `dev/pro`、UniGo 或 Mono 构建配置；也不要求额外安装 Task。

以下经验仍然适用：先确认编译器和 SDK，再构建；依赖缺失时明确失败；
把完整日志保留下来；实际运行 GDScript 验证产物；打包时按清单选择文件，
避免把旧引擎、其他架构或 .NET 目录一起复制进去。

## 环境与依赖

在 Windows PowerShell 中，从仓库根目录执行命令。
本入口使用 Python 3.10 或更新版本、SCons，以及 Visual Studio 的 C++ 工具链和 Windows SDK。
较新的 Visual Studio 需要较新的 SCons 才能正确识别，具体要求以[官方 Windows 构建文档]为准。

```powershell
python --version
python -m SCons --version
```

如果尚未安装 Python 构建依赖：

```powershell
python -m pip install scons zstandard
```

SCons 会自动发现 MSVC，不需要依赖当前 PowerShell 中是否有 `cl.exe`。
本次使用的 Python 3.12 需要额外的 `zstandard` 包；Python 3.14 起已内置相应能力。

首次准备官方原生依赖时，按需运行上游安装脚本：

```powershell
python misc/scripts/install_d3d12_sdk_windows.py
python misc/scripts/install_accesskit.py
python misc/scripts/install_angle.py
```

这些脚本下载依赖到 `%LOCALAPPDATA%\Godot\build_deps`，可能替换旧版本，日常增量编译不需要反复执行。
Direct3D 12、AccessKit 和 ANGLE 均保留；入口会检查依赖目录，缺失时给出对应安装命令。
入口会拒绝带 `custom.py` 的工作区。若该文件存在，先检查并把需要保留的配置另存到仓库外，
移开它后再运行，避免旧的裁剪选项影响本次原生构建。

## 构建、验证与打包

完整流程：

```powershell
python misc/misu/build_windows.py --jobs 16
```

入口默认执行 `all`，也可以分开运行：

```powershell
python misc/misu/build_windows.py build --jobs 16
python misc/misu/build_windows.py package
```

构建使用 `target=editor`、`arch=x86_64`、`module_mono_enabled=no` 和 `module_gdscript_enabled=yes`，
保留 Direct3D 12、Vulkan、OpenGL/ANGLE、AccessKit 及其他官方默认能力。
不做 2D、3D、导入器或平台模块裁剪，也不生成 C# 胶水、GodotSharp 程序集或 NuGet 包。
这是通常的编辑器构建，没有额外启用 `dev_build`、调试符号或完整 LTO。

默认并发数取逻辑处理器数与 16 中的较小值，也可以用 `--jobs` 指定。
首次完整构建耗时取决于机器和依赖，后续使用同样命令进行 SCons 增量构建。

构建完成后，脚本会读取生成的模块配置，检查 GDScript 已启用、Mono 未启用，
再执行 `--version` 和一个 headless GDScript 冒烟程序。冒烟程序验证脚本执行、Node3D 变换、
动态编译并调用 GDScript，且不存在 `CSharpScript` 类；成功时日志中会出现 `MISU_NATIVE_SMOKE_OK`。
这些检查不替代实际项目的 GUI、渲染和功能回归。

验证全局变换时，节点必须已经进入场景树。冒烟程序通过延迟调用执行检查，
避免在 `SceneTree._initialize()` 阶段读取尚未入树的节点。

## 增量构建与旧缓存方案

当前入口使用标准 MSVC/SCons，不添加外部编译器缓存。首次构建后继续执行相同命令，
SCons 会检查依赖并复用未变化的中间产物；不要为了增量构建先删除 `bin/obj`。

本次尝试过已有的 `sccache 0.16.0`。SCons/MSVC 默认把 `CXX` 定义为 `$CC`，
同时设置 C/C++ launcher 会形成重复包装；单独设置后，部分第三方目标仍报 `cannot find binary path`，
且缓存统计显示多数请求没有实际进入缓存。因此这套组合未纳入本次可重复使用的入口。
以后确需缓存优化时，再单独核实工具链兼容性、命中率和完整构建结果，不直接叠加旧实验参数。

## 产物与便携包

SCons 的主要产物仍位于 `bin`：

| 文件 | 用途 |
| --- | --- |
| `godot.windows.editor.x86_64.exe` | 原生编辑器和项目管理器 |
| `godot.windows.editor.x86_64.console.exe` | 同名编辑器的控制台启动器，需与主程序放在一起 |
| `D3D12Core.dll`、`d3d12SDKLayers.dll` | 上游构建复制出的 Direct3D 12 Agility SDK 组件 |

构建记录、验证项目和压缩包放在 `bin/misu`，由现有的 `bin` 忽略规则覆盖：

| 位置 | 内容 |
| --- | --- |
| `bin/misu/logs` | 带 UTC 时间戳的构建与 GDScript 冒烟日志 |
| `bin/misu/editor-build.json` | 源码提交、工作区状态指纹、版本、构建命令和运行文件 SHA-256 |
| `bin/misu/smoke` | 可重复运行的最小 GDScript 验证项目 |
| `bin/misu/packages` | 带版本和提交号的 ZIP 以及 `.zip.sha256` 校验文件 |

便携 ZIP 包含主程序、控制台启动器、上述 DLL、Godot 许可及版权文件、Agility SDK 许可和构建记录。
包内附带官方支持的 `_sc_` 标记，解压后会在程序旁生成 `editor_data`，保存这份本地编辑器的设置和缓存。
解压到可写目录后，运行主程序即可打开项目管理器；需要查看终端输出时运行控制台启动器。

单独执行 `package` 时，脚本会重新检查源码状态与运行文件校验值。
提交、源码或已验证的二进制发生变化后，需要重新执行构建；增量构建通过后才会更新记录并打包。
因此不会把旧记录对应的文件直接当作当前版本产物。

本次包是编辑器包。游戏项目导出所需的 `template_debug`、`template_release` 是另外的 SCons 目标，
应按需要构建相同版本、平台和架构的原生导出模板；不要混用旧 Mono 模板。

## 2026-10-21 本机实测

在 Intel Core i7-14700K、64 GB 内存的 Windows x86_64 机器上，使用 Python 3.12.10、
SCons 4.10.1 和 Visual Studio Community 2026 18.10.3 完成构建。
SCons 识别的工具链为 Visual Studio 14.5，Windows SDK 为 10.0.28000.0，并发数为 16。
基础源码版本为 `4.8.beta`；不使用外部编译缓存的一次完整构建耗时约 8 分 3 秒，
随后一次无源码变化的 SCons 检查约 12 秒。这些耗时仅对应上述机器和配置。

已验证编译链接、GDScript/Node3D 冒烟、动态脚本编译和 Mono 排除。
编辑器使用 NVIDIA GeForce RTX 4080 SUPER 成功初始化 Direct3D 12 / Forward+ 并正常退出。
便携包解压后再次通过 GDScript 冒烟、控制台启动器、Direct3D 12 编辑器启动及 `editor_data` 自包含模式验证，
同时检查了 ZIP CRC 和运行文件 SHA-256。原版引擎源码未作调整。

## 使用后的维护

今后遇到构建失败时，先看对应日志中的第一个错误，区分依赖、工具链、源码编译和打包步骤。
更新官方源码后，重新核对依赖安装脚本和构建参数，再执行同一入口。
如果需要增加目标平台、导出模板或调试配置，按实际需求扩展，并记录该组合的验证结果。
